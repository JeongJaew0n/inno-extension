# Inno Extension 디자인 시스템

**제품에 아직 적용하지 않았다.** 보고 판단하기 위한 것이다.

## 열어보기

```
open design/index.html
```

빌드도 서버도 필요 없다. 파일을 그대로 연다.

## 전략은 Material 3, 색은 우리 것

색을 하나씩 고르지 않는다. **시드 한 색에서 색조 팔레트를 뽑고, 색조를 역할에 배정한다.**
새 색이 필요하면 값을 찍는 게 아니라 "이게 어느 역할인가"를 정한다. 시드는 우리 Popup 이
쓰던 `#654cf2` 다.

| M3 개념 | 여기서 |
| --- | --- |
| 색조 팔레트 | 시드에서 계산. `primary` · `secondary` · `tertiary` · `neutral` · `neutral-variant` · `error` |
| 역할 | `primary` / `on-primary` / `primary-container` … 밝은 배색 배정 규칙 그대로 |
| 표면 단계 | 그림자 대신 `surface-container-*` 로 높이를 표현 |
| 상태 레이어 | hover·focus·pressed 를 `on-*` 색의 불투명도로. **hover 색을 따로 만들지 않는다** |
| 모양 스케일 | `none` → `full` 단계로 고정. 중간값을 쓰지 않는다 |
| 4dp 격자 | 간격을 4의 배수로 |

**`on-` 이 붙은 것은 그 배경 위에 올라가는 글자색이다.** 짝으로 쓰면 대비가 배정 규칙으로
보장돼서 눈으로 맞출 일이 없다.

### 우리 맥락에 맞춘 것

- 타입 스케일은 M3 이름(`label` / `body` / `title`)을 쓰되 **크기를 줄였다.** M3 의
  `display` · `headline` 은 앱 화면용이고, 우리 UI 는 남의 화면에 얹히는 작은 조각이다.
- 조작 요소 높이는 `24px` · `32px` 두 단계뿐이다. 기본은 `24px`.
- 어두운 배색은 아직 만들지 않았다. 같은 팔레트에서 배정만 바꿔 뽑으면 된다.

### HCT 대신 CIELCh

M3 는 색조 팔레트를 **HCT** 색공간에서 뽑는다. 여기서는 **CIELCh** 로 같은 일을 한다.
색조(hue)와 채도(chroma)를 고정하고 밝기 `L*` 만 0 → 100 으로 훑되, sRGB 밖으로 나가는
구간은 채도를 이진 탐색으로 줄여 담는다. 외부 라이브러리 없이 표준 라이브러리만으로 돈다.

HCT 는 밝기에 CAM16 의 `J` 를 쓰고 우리는 `L*` 을 쓴다. 같은 단계 번호라도 값이 정확히
일치하지는 않는다. **M3 팔레트를 그대로 재현하는 게 목적이 아니라 같은 전략을 쓰는 것이
목적이다.**

## `tokens.css` 는 손으로 고치지 않는다

```
python3 design/generate-tokens.py > design/tokens.css
```

색을 바꾸려면 **생성기의 시드·채도를 바꾸고 다시 돌린다.** 결과 파일을 직접 고치면 다음
생성에서 지워진다.

## 왜 React 가 아닌가

우리 UI 는 **Shadow DOM 에 평문 CSS 문자열을 넣는다.** React 컴포넌트로 만들면 정작 제품에서
쓸 수 없다. 여기서 만든 CSS 가 그대로 `shadow.innerHTML` 의 `<style>` 로 들어가야 의미가 있다.

## 빌드에 걸리지 않는다

| 경로 | 이 폴더를 보나 |
| --- | --- |
| `tsconfig.json` `include` | `src` · `vite.config.ts` · `manifest.json` — **안 본다** |
| Vite 번들 | `manifest.json` 진입점만 따라간다 — **안 본다** |
| `scripts/package-extension.mjs` | `dist` 만 ZIP 에 담는다 — **안 본다** |
| 네트워크 가드 테스트 | `src` 만 훑는다 — **안 본다** |

`npm run build` · `npm run package` 결과에 영향이 없다.

## 구성

| 파일 | 내용 |
| --- | --- |
| `generate-tokens.py` | 시드에서 팔레트·역할을 계산한다. **토큰의 정본** |
| `tokens.css` | 생성 결과. 팔레트 · 역할 · 상태 · 타입 · 모양 · 간격 · 높이 |
| `components.css` | 지금 제품에 실제로 있는 것만. 값 대신 토큰만 참조한다 |
| `index.html` | 눈으로 보는 페이지 |

## 왜 만들었나

Jira·Confluence 와 안 맞는 것은 받아들인다. **우리 것이라는 게 티나도 괜찮다.**
문제는 **우리 기능끼리 서로 다른 것**이다.

| | 지금 |
| --- | --- |
| 버튼 높이 | 24px 과 32px 이 섞여 있다 |
| 글자 | 11 · 12 · 13 · 14px 이 제각각 |
| 모서리 | 3 · 4 · 6 · 7 · 9 · 11 · 12px |
| 색 | 주입 UI 는 Atlassian 파랑, Popup 은 보라 |

## 두 가지 규칙만 기억하면 된다

### 1. `--inno-` 접두사를 뗄 수 없다

CSS 사용자 지정 속성은 **shadow 경계를 넘어 상속된다.** 호스트에 `all: initial` 을 걸어도
마찬가지다 — `all` 은 사용자 지정 속성을 건드리지 않는다. Jira 가 `--surface` 를 쓰고 있으면
우리 것과 섞인다.

### 2. 채운 버튼은 되돌릴 수 없는 동작에만

`저장` 이 대표적이다. 되돌릴 수 있는 것과 같은 모양이면 잘못 눌렀을 때 대가가 다르다는 것이
보이지 않는다.

## 적용할 때

한 번에 갈아엎지 않는다. 기능 하나씩 옮기고 그때마다 화면으로 확인한다. 옮길 때는 `<style>`
문자열 맨 위에 `tokens.css` 의 `:root` 블록을 넣고, 값 대신 토큰을 참조하게 바꾼다.

**아직 하지 않았다.** 어느 기능부터 옮길지는 따로 정한다.
