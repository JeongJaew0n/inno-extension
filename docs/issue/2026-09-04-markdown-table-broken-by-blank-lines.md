# 줄 사이에 빈 줄이 있으면 Markdown 표가 변환되지 않는다

- 발생일: 2026-09-04
- 상태: **원인 확정.** 확장 버그가 아니라 **입력 원문 문제.** 대응은 미적용
- 대상 문서: 개인 스페이스 `에러 테스트` 페이지 `2246476007`
- 신고 내용: 표가 Markdown 변환이 잘 안 된다

## 1. 결론

**변환기 버그가 아니다.** 변환에 넣은 Markdown 원문이 **줄마다 빈 줄이 끼어 있는 상태**였다.

Markdown 표는 **줄이 붙어 있어야** 표로 인식된다. 헤더와 구분선 사이, 행과 행 사이에 빈 줄이
있으면 표가 아니라 **각각 별개의 문단**이 된다. 이것은 Markdown 명세대로의 동작이고 `marked`도
그렇게 파싱한다.

코드 펜스는 안쪽 내용을 그대로 보존하므로 같은 조건에서도 **살아남는다.** 대신 원문에 빈 줄이
그대로 들어간다. 이 비대칭이 "표만 깨진 것처럼" 보이게 만든다.

## 2. 실측 — 현재 문서 상태

편집 화면에서 측정했다.

| 항목 | 값 |
| --- | --- |
| `table` 노드 | **0** |
| `\|...\|` 형태가 남은 문단 | **194** |
| 코드블럭 | 18 (정상) |
| Mermaid 컴포넌트 | 7 (정상) |

문단으로 떨어진 표 줄의 예다.

```text
| # | Method | 경로 | 파라미터 | K8s 오퍼레이션 |
|---|---|---|---|---|
| 1 | POST | /secret/eso | body {cluster, yaml} | dryRunCreate(동기) + create(비동기) |
```

**인라인 서식은 적용됐다.** `` `/secret/eso` ``의 백틱이 사라지고 코드 마크로 바뀌었다. 즉 각 줄은
Markdown 문단으로 정상 처리됐고, **표 구조만** 인식되지 않았다.

## 3. 재현

변환기에 직접 넣어 확인했다.

| 입력 | 결과 |
| --- | --- |
| 줄바꿈 1회 (`\n`) | **표 1개** · 문단 0 |
| 줄 사이 빈 줄 (`\n\n`) | 표 0 · **문단 4개** |
| 줄 사이 공백 한 칸 줄 (`\n \n`) | 표 0 · **문단 4개** |

빈 줄이 실제로 비었든 공백 한 칸이든 결과는 같다.

## 4. 원문에 빈 줄이 있었다는 증거

코드 펜스가 결정적 증거다. 같은 조건에서 펜스를 변환하면 이렇게 된다.

| 입력 | 코드블럭 내용 |
| --- | --- |
| 펜스 정상 | `"flowchart LR\n    A --> B"` |
| 펜스에 빈 줄 삽입 | `"\nflowchart LR\n\n    A --> B\n"` |

그리고 **실제 문서의 Mermaid 코드블럭을 읽은 값**이다.

```text
"\nflowchart LR\n\n    C[\"EsoCoreV1Controller<br/>?cluster=name\"] --> U[\"UseCase\"]\n\n    U --> ..."
```

앞에 빈 줄 하나, 줄 사이마다 빈 줄. **"펜스에 빈 줄 삽입"과 정확히 같은 형태다.**

정상 원문을 넣었다면 우리 변환기는 `"flowchart LR\n    A --> B"` 형태를 낸다. 앞뒤로 빈 줄을
붙이지 않는다. 따라서 **빈 줄은 변환기가 만든 것이 아니라 입력에 이미 있었다.**

## 5. 빈 줄은 어디서 왔나

**확인하지 못했다.** 다만 정황은 있다.

사용자가 공유한 원문에도 같은 특징이 보인다 — 빈 줄 자리가 완전히 빈 줄이 아니라 **공백 한 칸**이고,
문서 끝에 붙은 대화 로그가 한 줄씩 빈 줄로 분리돼 있다. 렌더된 화면(채팅 UI, 문서 뷰어 등)에서
복사하면 줄마다 블록이 분리되어 이런 형태가 되기 쉽다.

**원본 `.md` 파일에서 복사했다면 이 현상은 생기지 않는다.**

## 6. 왜 표만 깨져 보이나

| 요소 | 빈 줄 있을 때 | 이유 |
| --- | --- | --- |
| 제목 `#` | 정상 | 한 줄로 완결된다 |
| 문단·인라인 서식 | 정상 | 한 줄로 완결된다 |
| 코드 펜스 | **내용에 빈 줄이 섞이지만 유지** | 펜스 안은 그대로 보존된다 |
| 목록 | 항목이 흩어질 수 있음 | 연속성이 필요하다 |
| **표** | **완전히 깨짐** | **여러 줄이 붙어 있어야 성립한다** |

표는 Markdown에서 **가장 여러 줄에 의존하는 블록**이라 이 조건에 가장 취약하다.

## 7. 대응 후보

| 후보 | 내용 | 평가 |
| --- | --- | --- |
| **A** | 표처럼 보이는 줄이 문단으로 남으면 **경고를 띄운다** | **권장.** Popup이 이미 경고 개수를 보여준다. 원인을 즉시 알 수 있다 |
| B | 변환 전에 빈 줄을 자동으로 걷어낸다 | **권하지 않는다.** 의도한 문단 구분까지 지운다. 원문을 말없이 바꾸는 것은 위험하다 |
| C | 표 줄이 연속이 아니면 자동으로 이어 붙여 표로 만든다 | B와 같은 위험. 게다가 표가 아닌 `\|` 문단을 표로 오인할 수 있다 |
| D | 아무것도 하지 않고 문서로만 남긴다 | 사용자가 원인을 알 방법이 없다 |

**A를 권장한다.** 예를 들면 이런 문구다.

```text
표처럼 보이는 줄 194개가 표로 변환되지 않았습니다.
줄 사이의 빈 줄을 없애면 표로 변환됩니다.
```

자동 교정(B·C)은 하지 않는 편이 낫다. 이 변환기는 원문을 손실 없이 옮기는 것이 계약이고,
빈 줄이 의도된 문단 구분일 수도 있다.

## 8. 확인하지 못한 것

- 빈 줄이 삽입된 **정확한 경로**(어느 앱에서 복사했는지)를 확인하지 못했다.
- 목록·인용 등 다른 여러 줄 블록이 같은 조건에서 어떻게 깨지는지는 측정하지 않았다. 표만 확인했다.
