# 계획 — Jira 업무 생성 도우미

두 기능을 Jira 업무 생성 모달에 넣는다. 조사 기록은 [context.md](./context.md)에 있다.

## 범위

| 기능 ID | 이름 | 기본값 |
| --- | --- | --- |
| `createQuickDates` | 업무 생성 날짜 단축 | ON |
| `createTemplateInsert` | 업무 생성 템플릿 삽입 | ON |

둘 다 **업무 생성 모달 안에서만** 동작한다. 다른 화면은 건드리지 않는다.

## 비목표

- 업무를 대신 만들지 않는다. **`만들기` 버튼은 누르지 않는다.**
- 담당자·컴포넌트·스프린트 등 다른 필드는 채우지 않는다.
- 업무 상세 화면의 날짜 편집은 대상이 아니다. 다른 컴포넌트다.
- 네트워크를 쓰지 않는다. 화면에 이미 있는 것만 다룬다.

## 공통 — 모달 찾기

```
[data-testid="minimizable-modal.ui.modal-container.modal"][role="dialog"]
```

이 안에 `issue-create-modernised.*` 필드가 있을 때만 업무 생성 모달로 본다. 같은 컨테이너를
다른 모달도 쓰기 때문이다.

필드는 **컨테이너의 `<label>` 텍스트로 찾는다.** `customfield_10015` 같은 ID 는 인스턴스마다
다르다.

## 기능 1 — 날짜 단축

### 화면

모달 상단(요약 입력 위)에 우리 줄을 하나 넣고 버튼을 둔다.

```
[ 오늘부터 시작 ]
```

### 동작

누르면 이 순서로 진행한다.

```
1. 더 보기 펼치기      (이미 펼쳐져 있으면 건너뛴다)
2. 추가 필드 펼치기    (이미 펼쳐져 있으면 건너뛴다)
3. 시작 날짜 = 오늘
4. 기한     = 오늘 + 3일
```

각 날짜는 **달력 셀 클릭으로** 넣는다. 타이핑은 어떤 형식으로도 안 들어간다(context.md 참조).

```
1. 필드 컨테이너의 role="button" 트리거 클릭 → 달력이 열린다
2. 달력이 목표 달이 아니면 Next month / Previous month 로 이동
3. aria-label 이 `<일>, ` 로 시작하고 `<월>월 <연>` 을 포함하는 셀 클릭
```

### 실패와 복구

- 어느 단계든 대상을 못 찾으면 **거기서 멈추고 버튼에 `실패`를 잠깐 보여준다.**
  Jira 기본 동작은 그대로다.
- 이미 값이 들어 있으면 덮어쓴다. 사용자가 버튼을 누른 것이 의사 표시다.
- 모달이 닫히면 진행 중이던 것도 멈춘다.

### 수용 기준

- 접힌 모달에서 눌러도 두 단계를 펼치고 값을 넣는다.
- 이미 펼쳐진 모달에서 눌러도 같은 결과가 된다. **멱등하다.**
- 달을 넘는 경우(9/29 → 기한 10/2)가 정상 동작한다.
- 연을 넘는 경우(12/30 → 기한 1/2)가 정상 동작한다.
- 기능이 OFF 면 버튼이 주입되지 않는다.
- **`만들기`가 눌리지 않는다.**

## 기능 2 — 템플릿 삽입

### 트리거

설명 편집기가 **비어 있고 첫 글자가 `$`일 때만** 목록을 연다.

`/`는 Jira 가 이미 쓴다(`설명을 추가하거나 /를 입력하여 작업 및 Rovo를 사용합니다`). `$`는
비어 있다.

문장 중간의 `$`는 잡지 않는다. 금액 표기(`$100`)가 흔하다.

### 필터와 선택

백로그 prefix 태그와 같은 규칙을 쓴다.

| 키 | 동작 |
| --- | --- |
| `↓` `↑` | 항목 이동. 끝에서 돈다 |
| `Enter` `Tab` | 선택 삽입 |
| `Esc` | 목록만 닫는다 |
| 마우스 | hover 이동, 클릭 삽입 |

`$bug` 처럼 뒤에 글자를 붙이면 제목으로 거른다. 대소문자를 무시한다.

목록 맨 아래에 `＋ 템플릿 추가·관리…`를 둔다. **마우스로만 눌린다** — prefix 태그와 같은 이유다.

### 삽입

선택한 템플릿의 본문을 설명 편집기에 넣고 `$` 토큰은 지운다.

**서식으로 바꿔서 넣는다.** `## Goal` 이 글자가 아니라 진짜 제목이 된다.

경로는 `Markdown -> ADF -> 편집기 HTML -> 붙여넣기` 이고, 저장소에 이미 있는 변환기를 쓴다.
붙여넣기에 `text/html` 을 함께 실으면 **편집기가 그쪽을 우선하고 자기 Markdown 파서를 타지
않는다.** `text/plain` 만 보내면 편집기 파서에 맡기게 되는데 실측에서 그게 일정하지 않았다 —
같은 본문이 어떤 때는 제목이 되고 어떤 때는 글자로 남았다.

변환기는 `marked`(43KB)를 끌고 오므로 **쓸 때만 지연 로드한다.** 편집기 Markdown 변환 기능이
쓰는 방식과 같다.

### 템플릿 설정

prefix 태그와 같은 구조다.

| 종류 | 출처 | 숨기기 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| **내장** | 확장이 제공 | 가능 | 불가 | **불가** |
| **사용자** | 직접 추가 | 가능 | 가능 | 가능 |

내장 5종은 팀 표준(`jira-ticket` 스킬)의 유형별 골격이다.

```
작업      Goal · Output · Scope · Done
버그      Goal · Output · 현상 · 조치
에픽      Goal · Output · Scope
하위 작업  Goal · Output · Scope
문서      Goal · Output
```

**내장 템플릿은 설정에 저장하지 않는다.** 숨김 여부만 남긴다. 통째로 저장하면 다음 릴리즈에서
골격을 고쳐도 기존 사용자가 옛 것에 머문다.

### Popup 편집

`제목 · 표시 · 관리` 세 열의 표. prefix 태그 표와 같은 모양을 쓴다.

제목만으로는 내용을 알 수 없으므로 행을 펼쳐 본문을 보고 고칠 수 있게 한다.

### 수용 기준

- 빈 설명에 `$`를 치면 켜둔 템플릿 전체가 뜬다.
- `$bug`로 걸러진다.
- 선택하면 본문이 들어가고 `$`는 사라진다.
- 문장 중간의 `$`에는 뜨지 않는다.
- 내장 템플릿은 삭제 버튼이 없다.
- 한글 조합 중 오작동하지 않는다.
- 목록이 닫힌 상태에서는 어떤 키도 가로채지 않는다.
- 기능이 OFF 면 아무것도 주입되지 않는다.

## 만드는 순서

저장소 규칙대로 **카탈로그 → 설정 기본값 → 사이트 런타임 → spec → README** 순이다.

1. `src/sites/jira/createModal.ts` — 모달 찾기·펼치기·필드 찾기 (두 기능 공용)
2. `src/sites/jira/features/createQuickDates/` — 순수 로직(`contracts.ts`) + 런타임
3. `src/sites/jira/features/createTemplateInsert/` — 순수 로직 + 런타임
4. 카탈로그 등록, `content.ts` 등록
5. Popup 템플릿 표
6. 테스트
7. `spec/features/` 문서

## 테스트로 막을 것

순수 로직만 단위 테스트한다. DOM 조작은 브라우저 실측으로 확인한다.

- 날짜 더하기가 달·연을 넘는 경우
- 달력 셀 `aria-label` 만들기
- `$` 토큰 읽기 — 첫 글자일 때만
- 템플릿 필터
- 내장 템플릿은 삭제되지 않는다
- 설정 정규화가 깨진 값에서 기본값으로 떨어진다
