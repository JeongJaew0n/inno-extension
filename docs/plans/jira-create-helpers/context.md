# 맥락 — Jira 업무 생성 도우미

## 원 요청 (2026-09-21)

> 지금 jira에서 '업무 생성' 할 때 특정 필드를 자동으로 입력하게 하고 싶어.
>
> 지금 일단 '만들기'를 하면, 모달이 뜨고 모달 우상단의 '더보기' 를 누르고
> 거기서 '추가 필드' 까지 눌러야만 '시작 날짜', '기한' 이런게 떠.
>
> 그래서 원하는것.
> 1. 상단에 버튼 그룹 생성 - '오늘 부터 시작'. 이걸 누르면 그냥 날짜가 오늘로 박히고
>    기한은 오늘로부터 + 3일.
> 2. 템플릿 삽입. 문서 제일 처음에 `$`를 넣으면, 템플릿 제목들이 나오고 그 중에
>    선택한 템플릿이 마크다운으로 들어감.

## 실측 기록 (2026-09-21, 로그인된 Chrome)

**업무는 하나도 만들지 않았다.** 모달을 열고 DOM 을 읽은 뒤 `버리기`로 닫았다.

### 필드의 정체

| 라벨 | 필드 ID | 비고 |
| --- | --- | --- |
| 시작 날짜 | `customfield_10015` | 이 인스턴스의 값 |
| 기한 | `duedate` | Jira 표준 |

**필드는 라벨 텍스트로 찾는다.** `customfield_10015`는 인스턴스마다 달라질 수 있고,
컨테이너의 `<label>`이 `시작 날짜` / `기한`을 그대로 들고 있는 것을 확인했다. 저장소 규칙이
"빌드마다 바뀌는 값에 의존하지 않는다"이므로 의미 있는 쪽을 쓴다.

### 펼치기는 2단이다

```
만들기
 └ [더 보기]  issue-create-modernised.ui.header.toggle-expand-button
    └ [추가 필드(6개)]  issue-create.ui.modal.create-form.layout-renderer
                        .fields-container.collapsible-area-header.collapsible-area-header
       └ 그때야 6개가 DOM 에 생긴다
```

접힌 상태에서도 `duedate` 컨테이너는 DOM 에 있다. **다만 속이 비어 있다** — `innerHTML`이
29자짜리 빈 껍데기다. 아코디언을 열어야 내용이 마운트된다.

`···` 버튼(`필드 구성`, `사용하지 않는 필드 숨기기`)은 이 경로와 무관하다. 사용자가 말한
'더보기'는 헤더의 확장 버튼이다.

### 타이핑으로는 값이 안 들어간다 (이게 핵심 제약)

마운트된 뒤에도 바로 입력이 아니다. `role="button"` 트리거이고, 클릭해야
`#duedate-field`(`aria-label="기한"`, `type=text`)가 생긴다.

그 입력창에 **7가지 형식을 전부 넣어봤고 전부 실패했다.**

| 넣은 값 | 결과 |
| --- | --- |
| `2026-09-21` | No options |
| `2026/09/21` | No options |
| `2026. 9. 21.` | No options |
| `21/09/2026` | No options |
| `09/21/2026` | No options |
| `2026년 9월 21일` | No options |
| `20260921` | No options |

React controlled input 우회(native value setter + `input` 이벤트)까지 썼는데도 안 된다.
**그 입력창은 값을 받는 곳이 아니라 달력 검색창이다.**

### 되는 방법 — 달력 셀 클릭

날짜 셀은 `aria-label`을 들고 있다.

```
aria-label="24, 목요일 9월 2026"
            ^일  ^요일   ^월   ^연
```

`24, 목요일 9월 2026` 셀을 클릭하니 필드가 `기한 2026년 9월 24일`로 바뀌는 것을 확인했다.
달 이동 버튼도 있다 — `Previous year` / `Previous month` / `Next month` / `Next year`.

## 결정

### 기능을 둘로 나눈다

| 기능 ID | 내용 |
| --- | --- |
| `createQuickDates` | 모달 상단 버튼 그룹. `오늘부터 시작` |
| `createTemplateInsert` | 설명 첫 글자 `$` → 템플릿 목록 → 삽입 |

**`$` 트리거는 키 입력을 가로챈다.** 날짜 버튼만 쓰고 템플릿은 끄고 싶을 수 있어서 토글을
나눈다. 백로그 prefix 태그와 설명 편집 버튼을 따로 둔 것과 같은 판단이다.

### 템플릿은 Popup 에서 사용자가 관리한다

사용자가 고른 안이다. 백로그 prefix 태그와 같은 구조를 쓴다 — 내장 목록은 코드에 두고 설정에는
숨김 여부만, 사용자 템플릿은 설정에 저장.

기본값은 팀 표준(`jira-ticket` 스킬)의 유형별 골격 5종이다. 근거는 PAAS `10. 개발 프로세스`의
"Description 에 Goal 과 Output 을 작성" 조항이고, 스킬이 그것을 유형별 템플릿으로 갖고 있다.

| 유형 | 섹션 |
| --- | --- |
| 작업 | Goal · Output · Scope · Done |
| 버그 | Goal · Output · 현상 · 조치 |
| 에픽 | Goal · Output · Scope |
| 하위 작업 | Goal · Output · Scope |
| 문서 | Goal · Output |

### 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| REST API 로 필드 값 설정 | **쓰기(PUT)다.** 이 저장소의 API 규칙은 읽기(GET)만이다 |
| 날짜 입력창에 텍스트 주입 | 7형식 전부 실패. 위 실측 |
| `customfield_10015` 선택자 고정 | 인스턴스마다 다르다. 라벨 텍스트가 안정적이다 |
| 템플릿을 코드에만 내장 | 팀 사정이 바뀔 때마다 릴리즈해야 한다 |
| `/` 트리거 | Jira 가 이미 쓴다(`/를 입력하여 작업 및 Rovo를 사용합니다`) |

## 열린 질문

- 템플릿을 **Markdown 원문 그대로** 넣을지, 편집기가 서식으로 해석하게 할지 실측하지 않았다.
  Atlassian 편집기가 붙여넣기 Markdown 을 해석하는 경로가 있는데 이 모달의 편집기에서도
  그런지 확인해야 한다.
- `오늘부터 시작`이 접힌 모달에서 눌리면 폼이 두 단계 펼쳐진다. 화면이 확 바뀌는 셈인데
  거슬리는지는 써봐야 안다.
