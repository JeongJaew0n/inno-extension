# 설명 편집 버튼 — 설계

- 상태: **구현 완료 · 실사용 확인 대기**
- 작성일: 2026-09-17
- 실측: [context.md](./context.md)

## 1. 핵심 — 새 동작을 만들지 않는다

**아래쪽 `취소`·`저장` 버튼을 그대로 누른다.** 편집 상태를 우리가 해제하지도, 저장 요청을 우리가
보내지도 않는다.

그래야 Jira가 정한 동작이 그대로 유지된다 — 변경 사항이 있을 때 확인 대화상자를 띄울지,
초안을 남길지 전부 Jira의 판단이다. 우리가 흉내 내면 언젠가 갈린다.

## 2. 동작 계약

| 항목 | 값 |
| --- | --- |
| 나타나는 조건 | 설명 **편집 컨테이너 안에** 취소 버튼이 있을 때만 |
| 자리 | `설명` 라벨 줄 (`Markdown 복사`와 같은 자리) |
| 버튼 | `저장` 다음 `취소` (아래쪽 버튼 줄과 같은 순서) |
| 하는 일 | 아래쪽 해당 버튼의 `click()` |
| 기본값 | **ON** |

- 편집 중이 아니면 붙지 않는다. 취소할 것이 없다.
- 클릭 시점에 버튼을 **다시 찾는다.** 그 사이 편집이 끝났을 수 있다.
- 못 찾으면 아무것도 하지 않고 콘솔에 남긴다.

## 3. 가장 큰 위험 — 남의 댓글을 취소시키는 것

두 버튼의 `data-testid`가 `comment-cancel-button` · `comment-save-button`이다. **진짜 댓글
입력창에도 같은 testid가 있다.** 문서 전체에서 찾으면 사용자가 쓰던 댓글이 날아가고, **저장 쪽은
쓰다 만 댓글이 그대로 등록된다.**

**설명 편집 컨테이너 안에서만 찾는다.** 회귀 테스트로 박았다.

## 3-1. `저장`은 `취소`와 다르게 그린다

**저장은 되돌릴 수 없다.** 위쪽에 있으면 아래쪽보다 잘못 눌리기 쉬운데, 두 버튼이 같은 모양이면
그 위험이 커진다.

| 버튼 | 모양 |
| --- | --- |
| `취소` | 배경 없음, 회색 글자 |
| `저장` | **파란 배경(#0c66e4), 흰 글자** |

## 4. 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 저장 전 확인 절차 추가 | Jira 가 하던 대로 둔다. 흉내 내면 갈린다 |
| 편집 상태를 직접 해제 | Jira 동작과 갈린다 |
| 댓글 편집기에 같은 버튼 | 요청 범위 밖 |
