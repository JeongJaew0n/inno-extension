# Jira 설명 Markdown 복사 — 이미지 포함 설계

- 상태: 구현 완료 · 실사용 확인 대기 (Q1~Q4 측정, 네트워크 예외·화면 크기 결정 2026-10-12)
- 작성일: 2026-10-12
- 대상 기능: `descriptionMarkdownCopy` (Jira 설명 Markdown 복사)

## 1. 요청

Jira 설명을 Markdown 으로 복사해 **VS Code** 에 붙여넣을 때 이미지도 보이게 한다(2026-10-12 사용자).
붙여넣은 `.md` 는 커밋하지 않는다 — 읽기·정리용이다.

## 2. 결정

**이미지를 Markdown 안에 data URI 로 넣는다.**

```markdown
![설계도.png](data:image/png;base64,iVBORw0KGgo…)
```

| 대안 | 고르지 않은 이유 |
| --- | --- |
| 주소만 넣기(지금 읽기 화면) | 첨부 주소는 로그인·토큰이 있어야 열린다. VS Code 에서 깨진다 |
| 서식 클립보드(HTML 에 이미지) | VS Code `.md` 에는 평문이 붙는다 |
| 이미지 파일 따로 받기(ZIP) | 커밋하지 않는 용도라 두 단계일 이유가 없다 |
| 클립보드에 이미지 넣기 | 웹 클립보드는 PNG 한 장만 담는다. 글과 여러 장을 함께 못 담는다 |

## 3. 런타임 흐름

1. `Markdown 복사` 를 누른다(지금과 같은 버튼).
2. 지금처럼 Markdown 을 만든다. 이미지 자리는 일단 표식으로 둔다.
3. 이미지마다 바이트를 받아 base64 로 바꾼다. **누를 때만** 받는다.
4. 표식을 `![이름](data:<mime>;base64,…)` 로 바꿔 평문으로 복사한다.
5. 라벨: `복사됨 · 이미지 3` / 일부 실패 시 `복사됨 · 이미지 2/3`.

이미지 하나가 실패해도 복사는 한다. 그 자리는 지금처럼 `(이미지 첨부)` 로 남기고 콘솔에 이유를 남긴다.

## 4. 열린 질문 — 측정이 필요하다

| # | 질문 | 갈리는 것 |
| --- | --- | --- |
| **Q1** | 설명 **읽기 화면**의 `<img>` 가 어느 주소에서 오는가. 같은 오리진(`pms-innogrid.atlassian.net`)인가, 미디어 서버(다른 오리진)인가. `blob:` 인가 | 같은 오리진 → content script 의 `fetch` 로 받는다. `blob:` → 그대로 읽는다. **다른 오리진** → CORS 허용 여부를 봐야 하고, 없으면 service worker + `host_permissions` 가 필요하다(권한이 늘어 사용자 결정 필요) |
| Q2 | 설명 **편집 중**(ADF 경로) 이미지는 어떻게 찾는가. ADF `media` 노드에는 `id`·`collection` 만 있고 주소가 없다 | 편집기 DOM 에 그려진 `<img>` 와 짝을 지을 수 있으면 Q1 과 같은 방법. 아니면 편집 중에는 지금처럼 `(이미지 첨부)` 로 둔다 |
| Q3 | 이미지 크기 분포 | 한 장·전체 상한(초안: 장당 5MB, 합계 20MB). 넘으면 그 이미지는 `(이미지 첨부 — 너무 큼)` |
| Q4 | VS Code 미리보기가 data URI 이미지를 보여주는가 | [가정] 보여준다. 이 Mac 의 VS Code 에서 확인한다 |

## 5. 네트워크 규칙

이미지를 받으려면 요청이 나간다. CLAUDE.md '네트워크는 예외다' 에 따라 처리한다.

| 규칙 | 여기서 |
| --- | --- |
| 표시 | 카탈로그 `descriptionMarkdownCopy` 에 `usesNetwork: true` |
| 범위 | GET 만 |
| 시점 | `Markdown 복사` 를 누를 때만 |
| 대상 | **Q1 결과에 달렸다.** 같은 오리진 상대 경로면 규칙 그대로. 다른 오리진이면 규칙 밖이라 **구현 전에 사용자 결정**을 받는다 |
| 자리 | `src/sites/jira/api/` (테스트의 `ALLOWED` 안) |
