# 인사말 복사 갱신 — 구현 체크리스트

착수 전 [spec.md](./spec.md) 8절의 결정을 확정한다.

## 0. 선결

- [ ] Q1 후킹 값 사용 시 사용자에게 표시할지 확정
- [ ] Q2 저장 위치 확정 (`chrome.storage.session` 권장)
- [ ] Q3 확정 후 결과 모달 유무 조사 시점 확정

## 1. MAIN world 후킹

- [ ] 아마란스용 MAIN world 스크립트 추가 (`src/sites/amaranth/main.ts`) — Confluence `main.ts`를 선례로 삼는다
- [ ] `manifest`/빌드 설정에 MAIN world 등록
- [ ] `XMLHttpRequest.open/send`와 `fetch`를 감싸 **관찰만** 한다. 원본 호출은 그대로 통과시킨다
- [ ] 중복 주입 가드 (Confluence의 `bridgeFlag`와 같은 방식)
- [ ] 대상은 `/human/common/judgeTimeManagement/` 아래 **POST**로 한정
- [ ] `getTodayComeLeaveInfo`, `confirmApplicationStatus`는 조회이므로 제외
- [ ] 실패 응답은 무시한다
- [ ] 예외를 삼켜 페이지 동작을 막지 않는다

## 2. 시각 추출

- [ ] 응답에서 `HH:MM` 형태 값을 찾으면 그것을 쓴다
- [ ] 없으면 **API 성공 시점의 클라이언트 시계**를 쓴다
- [ ] **응답 본문을 저장하거나 로그로 남기지 않는다.** 사번·부서 코드가 들어 있다
- [ ] 출근인지 퇴근인지 구분한다. 퇴근 기록으로 출근 인사말을 만들면 안 된다

## 3. 저장과 소비

- [ ] 날짜(`YYYY-MM-DD`)를 포함해 저장한다
- [ ] 읽을 때 날짜가 오늘이 아니면 무시한다
- [ ] `인사말 복사`의 우선순위: **위젯 DOM > 후킹 값**
- [ ] 위젯에 값이 있으면 항상 위젯이 이긴다
- [ ] 둘 다 없으면 종전대로 `출근 기록 없음`을 보여준다. 현재 시각으로 대체하지 않는다

## 4. 건드리지 않는 것

- [ ] 기존 `인사말 복사` 버튼의 위치·라벨·기본 동작 유지
- [ ] 출근·퇴근 위임 버튼 동작 유지
- [ ] 모달에 버튼을 넣지 않는다

## 5. 테스트

- [ ] 시각 추출 — 응답에 시각이 있을 때 / 없을 때
- [ ] 날짜가 다른 저장값은 무시하는지
- [ ] 위젯 값이 있으면 위젯이 이기는지
- [ ] 출근·퇴근 구분
- [ ] 실패 응답에서 아무것도 저장하지 않는지
- [ ] 기존 테스트 무회귀

## 6. 실제 확인 (다음 출근 때)

- [ ] 출근 확인 직후 **새로고침 없이** `인사말 복사`가 올바른 시각을 내는지
- [ ] 새로고침 후에도 같은 값인지 (위젯과 일치)
- [ ] **확정 API의 이름과 응답 형태를 기록한다** — 이 계획의 미확인 항목
- [ ] 확정 후 결과 모달이 뜨는지, 뜬다면 시각이 있는지
- [ ] 모달을 끈 상태(`오늘 하루 띄우지 않기`)에서도 동작하는지
- [ ] **근태를 임의로 기록하지 않는다.** 사용자가 실제로 출근할 때만 확인한다

## 7. 문서

- [ ] `spec/features/`에 아마란스 근태 기능 문서가 있으면 갱신, 없으면 `spec/product-overview.md` 변경 이력에 추가
- [ ] 변경 이력은 **섹션 안에** 넣는다 (파일 끝에 붙이지 않는다)
- [ ] 확정 API 형태를 이 계획 문서에 반영하고 상태를 갱신한다
- [ ] README 기능 설명에 영향이 있으면 갱신
