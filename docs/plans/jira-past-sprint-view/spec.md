# 지난 스프린트 보기 — 기술 검토

- 상태: **검토 · 결정 대기**
- 작성일: 2026-09-18
- 실측: [context.md](./context.md)

## 1. 결론 먼저

**할 수 있다. 다만 요청한 3번(보드 카드를 갈아끼우기)은 권하지 않는다.**

| 시나리오 | 가능한가 | 판정 |
| --- | --- | --- |
| 1. 스프린트 선택 셀렉트 | **쉽다** | 문제 없음 |
| 2. API 로 지난 스프린트 업무 조회 | **된다** | 실측 완료 |
| 3. 보드 카드를 지우고 갈아끼우기 | 되기는 한다 | **권하지 않는다** |

3번이 걸리는 이유는 "안 된다"가 아니라 **"되는데 조용히 망가진다"** 이기 때문이다.

## 2. 먼저 결정할 것 — 제품의 전제를 깬다

`CLAUDE.md` 와 `spec/product-overview.md` 에 이렇게 박혀 있다.

> **네트워크 요청을 보내지 않는다.** 모든 기능은 이미 로드된 화면의 DOM만 읽고 쓴다.
> 사내 시스템의 API를 호출하지 않는 것이 이 확장의 전제다.

이 기능은 그 전제를 깬다. 깨도 된다고 하셨으니 **바꾸는 것 자체는 결정된 것**으로 본다. 다만
바꾸면 따라오는 것들이 있다.

| 항목 | 바뀌는 것 |
| --- | --- |
| 리뷰 부담 | 지금까지는 "DOM만 만진다" 한 줄로 안전성을 설명할 수 있었다. 이제 **무엇을 언제 어디로 보내는지**를 문서로 설명해야 한다 |
| 권한 | 같은 오리진이라 `host_permissions` 는 필요 없다. 실측으로 확인했다 |
| 인증 | 브라우저 세션 쿠키를 그대로 쓴다. **토큰을 저장하지 않는다** |
| 범위 | **읽기(GET)만.** 쓰기 API 는 이 기능에 필요 없고, 열어두면 사고의 폭이 달라진다 |

전제를 "네트워크 요청을 하지 않는다"에서 **"같은 오리진에 읽기 요청만 한다"** 로 좁혀서 다시
쓰는 것을 제안한다. 문장을 지우는 것보다 낫다.

## 3. 3번을 권하지 않는 이유

실측하니 카드를 지워도 **React 가 되살리지 않았다.** 45초를 두어도, 업무 모달을 열고 닫아도
그대로였다. 얼핏 좋은 소식 같지만 반대다.

React 는 **자기 가상 DOM 이 맞다고 믿는 것만 고친다.** 우리가 실제 DOM 을 건드리면 그때부터 둘이
어긋난 채 남는다. 되살아나지 않는 이유가 그것이다.

어긋난 상태에서 그 자리가 다시 렌더되면 **결과가 정해져 있지 않다.** 그리고 보드는 다시 렌더될
일이 아주 많다.

| 사용자가 하는 일 | 어긋난 DOM 에서 |
| --- | --- |
| 카드 드래그로 상태 변경 | 엉뚱한 업무가 옮겨질 수 있다 |
| 필터 변경 | 지난 스프린트 카드에 현재 스프린트 필터가 먹는다 |
| `스프린트 완료` | **지금 보이는 것과 실제 대상이 다르다** |
| 다른 사람의 변경이 밀려옴 | 우리 카드와 진짜 카드가 섞인다 |

가장 나쁜 것은 **사용자가 지금 무엇을 보고 있는지 구분할 수 없다는 점**이다. 지난 스프린트
카드가 진짜 보드처럼 생겼는데 드래그가 먹으면, 끝난 스프린트를 고치고 있는 줄도 모른다.

## 4. 대안 셋

| | 안 | 3번을 어떻게 대신하나 | 위험 | 만드는 비용 |
| --- | --- | --- | --- | --- |
| **A** | **오버레이 패널** | 보드 위에 우리 패널을 띄우고 거기에 지난 스프린트 업무를 그린다. 보드 DOM 은 **건드리지 않는다** | 낮음 | 중 |
| B | 보드 카드 갈아끼우기 (요청안) | 요청대로 | **높음** | 중 |
| C | 새 탭에 우리 화면 | 확장 페이지를 열어 거기에 그린다 | 가장 낮음 | 중 |

**A 를 권한다.** 보드 화면 안에서 보고 싶다는 요구를 그대로 만족시키면서, React 와 싸우지 않는다.
패널은 우리가 100% 소유하므로 정렬·그룹·열 구성을 우리 마음대로 할 수 있고, **읽기 전용이라는
것이 눈에 보인다.**

### A 안의 모습

```
[활성 스프린트 보드]
 버전 Epic 유형 레이블 빠른필터   [스프린트: Jazz-v1.0-Sprint1 ▾]  ← 우리 셀렉트
 ─────────────────────────────────────────────────────────────
 (종료된 스프린트를 고르면)

 ┌─ 지난 스프린트: Sprint0 (2026-08-12 ~ 08-26) · 읽기 전용 ──── [닫기] ─┐
 │  BACKLOG      해야 할 일      IN-PROGRESS      완료               │
 │  ...카드...   ...카드...      ...카드...       ...카드...          │
 └──────────────────────────────────────────────────────────────────┘
```

- 보드 카드는 그대로 두고 **패널이 그 위를 덮는다.** 닫으면 원래 보드가 그대로 남는다
- 카드는 클릭하면 업무를 연다(기존 동작). 드래그는 **하지 않는다** — 끝난 스프린트다
- 셀렉트에서 활성 스프린트를 다시 고르면 패널을 닫는다

## 5. 만들어야 하는 것

| 조각 | 내용 |
| --- | --- |
| 스프린트 목록 | `GET /rest/agile/1.0/board/{boardId}/sprint` — 활성 + 종료 |
| 업무 조회 | `GET /rest/agile/1.0/sprint/{sprintId}/issue` — **100건씩 페이지네이션** (측정한 스프린트가 112건) |
| 필드 추리기 | 응답의 `fields` 가 134개다. 카드에 쓸 것만 뽑는다 |
| 컬럼 구성 | 보드의 컬럼 이름을 어디서 가져올지. 업무 상태 이름으로 묶는 것이 가장 단순하다 |
| 셀렉트 UI | 필터 줄 오른쪽. `활성 스프린트 정보` 칩과 자리가 겹치므로 배치를 같이 정해야 한다 |
| 패널 UI | Shadow DOM 격리 |
| 실패 처리 | 401·403·429·네트워크 오류. **조용히 실패하지 않는다** |

## 6. 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 쓰기 API | 이 기능에 필요 없다. 열어두면 사고의 폭이 달라진다 |
| 보드 DOM 교체 | 3절 |
| 지난 스프린트에서 드래그·편집 | 끝난 스프린트다. 읽기 전용이 정직하다 |
| 응답 캐시를 `chrome.storage` 에 저장 | 업무 내용이 로컬에 남는다. 필요해지면 그때 따로 정한다 |

## 8. 남는 위험

- **Jira 내부 REST 가 아니라 공개 Agile API 라 비교적 안정적이다.** 다만 Atlassian 이 바꾸면
  깨진다
- 업무가 많은 스프린트는 요청이 여러 번 나간다. 112건이면 2번이다
- 권한이 없는 보드에서는 403 이 온다. 그때 무엇을 보여줄지 정해야 한다
