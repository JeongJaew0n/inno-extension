# 계획 — Mermaid 를 넣기 전에 서버 초안을 기다린다

## 문제

코드블럭으로 감싼 Markdown 을 변환하면 flowchart 가 오류로 그려진다. 되돌린 뒤 다시 변환하면 정상이다.

## 원인 (실측 2026-10-01, 실험 페이지)

- Mermaid 매크로는 우리가 넣은 순번(`guestParams.index`)으로 **서버에 저장된 초안**의 N번째 코드블럭을 읽는다.
- 서버 초안은 편집 후 **약 10.7초** 늦게 반영된다(화면은 즉시).
- 변환은 코드블럭 벗기기 0.6초 뒤에 매크로를 넣는다 → 매크로가 벗기기 전 초안을 읽는다.
  - 초안에 그 순번이 없으면 `Code block under with position N not found`
  - 다른 블록이 있으면 `No diagram type detected … for text: <그 블록>`
- 매크로는 실패 뒤 스스로 다시 그리지 않는다(15초 관찰). 새로고침하면 그 시점 초안으로 다시 그린다.

## 고침

Mermaid 단계에서 매크로를 넣기 **전에** 서버 초안을 읽어, 각 후보의 순번 자리에 그 Mermaid 원문이 있는지 본다.

| 상황 | 동작 |
| --- | --- |
| 이미 맞다 (두 번째 실행 등) | 기다리지 않고 바로 넣는다. GET 1회 |
| 아직 아니다 | 1초마다 다시 읽는다. 버튼에 `서버 저장 대기 n초` |
| 30초 안에 안 맞는다 | 그대로 넣고 "오류로 보이면 새로고침" 안내를 남긴다 (지금 동작과 같다) |
| 초안을 못 읽는다 (권한·네트워크) | 기다리지 않고 넣는다. 같은 안내 |

매크로를 넣어도 코드블럭 순번은 바뀌지 않는다(원본이 같은 자리의 접힌 영역으로 들어간다). 그래서 넣기 전 한 번 맞추면 된다.

## 네트워크 — 특별 관리

| 규칙 | 여기서 |
| --- | --- |
| 표시 | 카탈로그 `pageMarkdownAppend` 에 `usesNetwork: true` |
| 범위 | `GET /wiki/rest/api/content/{pageId}?status=draft&expand=body.atlas_doc_format` 만 |
| 시점 | `Markdown 변환` 을 눌렀고 Mermaid 후보가 있을 때만 |
| 오리진 | 상대 경로. 세션 쿠키. 토큰 저장 없음 |
| 자리 | `src/sites/confluence/api/` (테스트 ALLOWED 에 추가) |

## 완료 조건

- 단위: 초안 ADF 에서 코드블럭 원문 순서 뽑기(중첩 포함), 맞는지 판정, 페이지 id
- e2e: 초안 API 를 픽스처로 — 처음엔 옛 초안, 몇 번 뒤 새 초안을 돌려줄 때 기다렸다 넣는지
- 실험 페이지에서 처음 상태(코드블럭 하나) → 한 번 변환 → 다이어그램 정상
- spec · README · troubleshooting 갱신
