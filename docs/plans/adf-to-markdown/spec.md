# 편집 중 Markdown 복사 — 설계

- 상태: **구현 중**
- 작성일: 2026-09-18

## 1. 왜 새 변환기가 필요한가

`Markdown 복사`는 **읽기 화면의 렌더러**(`.ak-renderer-document`)를 HTML 태그째로 훑는다. 편집
중에는 그 렌더러가 없다. 편집기 DOM 을 대신 먹이면 안 된다 — 실측값이다.

| 항목 | 편집기 DOM |
| --- | --- |
| `[data-testid="renderer-code-block"]` | **0개.** 변환기의 코드블럭 진입점이 없다 |
| 코드블럭 | CodeMirror. `<pre><code>` 가 아니다 |
| 긴 코드블럭 | **30줄 안팎까지만 렌더된다.** 뒷부분이 사라진다 |

## 2. 채택 — ProseMirror 에서 ADF 를 직접 읽는다

```
editorViewFound : true
doc.toJSON()    : { type: 'doc', content: [heading, codeBlock, extension, expand] }
```

DOM 추측도 잘림도 없다. **원문 그대로**다. 브리지는 Jira·Confluence 양쪽에 이미 있어서 읽기
액션 하나만 더한다.

## 3. 사용자에게 보이는 변화는 하나뿐

| 항목 | 노출 |
| --- | --- |
| ADF → Markdown 변환기 | 내부. UI·설정 없음 |
| 브리지 `read-doc` | 내부 |
| 카탈로그·Popup | **추가 없음** |
| **`Markdown 복사` 버튼** | **편집 중에도 사라지지 않는다** |

## 4. Markdown 에 대응물이 없는 노드 — 텍스트로 떨어뜨린다 (A안)

| 노드 | 처리 |
| --- | --- |
| `extension`(Mermaid 매크로 등) | **버린다.** 원본 코드블럭이 어차피 옆에 남는다 |
| `expand` | 껍데기를 벗기고 내용만. 제목이 있으면 굵은 한 줄로 |
| `panel` | 껍데기를 벗기고 내용만 |
| `status` · `date` · `mention` · `emoji` | 텍스트로 |
| `media`(첨부) | `(이미지 첨부)` — 붙여넣는 쪽에서 쓸 수 없는 참조를 넣지 않는다 |
| `media`(external) | `![](url)` |
| 모르는 노드 | 안에 든 텍스트만 건진다 |

주석이나 표식으로 남기지 않는다. 복사의 목적이 **다른 곳에 옮겨 쓰기**인데 표식은 거기서
쓰레기가 된다.

## 5. 두 경로의 출력이 갈리지 않게 한다

읽기 모드(렌더러 경로)와 편집 모드(ADF 경로)가 **같은 문서에서 같은 Markdown** 을 내야 한다.
이스케이프·표 칸·목록 들여쓰기·코드 펜스 규칙을 `platform/markdown/format.ts` 로 모아 두 경로가
함께 쓴다.

## 6. 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 읽기 모드를 ADF 경로로 바꾸기 | 잘 돌아가는 것을 건드리지 않는다. 옮긴다면 별도 작업 |
| 편집기 DOM 긁기 | 코드블럭이 깨지고 긴 블록은 내용이 사라진다 |
| 새 버튼·새 설정 | 기존 버튼이 한 상태에서 더 동작할 뿐이다 |
