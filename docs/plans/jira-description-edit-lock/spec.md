# 계획 — Jira 설명 편집 막기

## 요청 (2026-09-28)

> jira 업무 클릭하면 바로 편집으로 들어가는데, '편집 막기' 토글 기능 하나 만들자.
> 전역 공유되는 옵션이고, ui와 jira 업무 상에서도 가능함. markdown 복사 왼쪽에 추가하면돼.
>
> 해당 기능이 켜져있으면 본문 클릭으로 편집이 막힘. 대신 '편집' 버튼을 또 하나 만들어줘.
> 꺼져있으면 그냥 편집 버튼 안보이고 클릭으로 기본 jira기능인, 클릭하면 편집되게.

## 설계

기능 하나(`descriptionEditLock`)에 옵션 하나(`locked`)를 둔다.

| 값 | 뜻 |
| --- | --- |
| 기능 ON (카탈로그 토글) | 설명 라벨 줄에 `편집 막기` 스위치가 보인다 |
| `locked: true` | 본문 클릭으로 편집되지 않는다. `편집` 버튼이 나타난다 |
| `locked: false` (기본) | Jira 기본 동작. `편집` 버튼 없음 |

**`locked` 를 기능 ON/OFF 와 합치지 않는다.** 합치면 끄는 순간 런타임이 내려가 스위치도 사라지고,
Jira 화면에서 다시 켤 방법이 없다. "ui 와 jira 업무 상에서도 가능" 을 못 지킨다.

**전역 공유**는 `chrome.storage.sync` 에 저장해서 얻는다. 한 탭에서 바꾸면 `storage.onChanged` 로
다른 탭과 Popup 이 같이 바뀐다.

## 자리

`설명` 라벨 줄, **`Markdown 복사` 왼쪽**. Markdown 복사 호스트가 이미 있으면 그 앞에 끼우고,
없으면 줄 끝에 붙인다(런타임 등록 순서도 앞에 둔다).

```
설명   [편집 막기 ●] [편집]  [Markdown 복사]
```

`편집` 버튼은 `locked` 이고 **읽기 상태일 때만** 보인다. 편집 중에는 누를 이유가 없다.

## 막는 방법

`window` capture 단계에서 `click` 을 가로채 `stopImmediatePropagation` 한다. React 는 루트에서
이벤트를 받으므로 거기 닿기 전에 끊으면 Jira 의 편집 전환이 일어나지 않는다.

- **설명 필드 안의 클릭만** 막는다.
- **렌더러 안의 링크·버튼·체크박스 등은 통과시킨다.** 펼치기(expand) 토글이나 링크까지 죽이면
  읽기가 불편해진다. 판단 기준을 렌더러 안으로 한정하는 이유는, 설명 전체를 감싸는 Jira 의
  클릭 영역 자체가 `role="button"` 일 수 있어서다 — 그걸 통과 대상으로 보면 아무것도 안 막힌다.
- `preventDefault` 는 하지 않는다. 링크 이동과 텍스트 선택은 그대로 둔다.

`편집` 버튼은 잠깐 통과 플래그를 세우고 본문에 `click()` 을 보낸다. Jira 가 원래 받던 클릭과 같은
경로로 편집에 들어간다.

## 비목표

- 키보드(`Enter`)로 편집에 들어가는 경로는 막지 않는다. 요청이 "클릭" 이다.
- 댓글·다른 필드의 클릭 편집은 건드리지 않는다.

## 확인하지 못한 것

[미정] 브라우저 자동화 연결이 끊긴 상태에서 만들었다. Jira 가 편집 전환을 `click` 으로 하는지
`mousedown`/`mouseup` 으로 하는지 **실측하지 못했다.** Atlaskit InlineEdit 가 `click` 을 쓰는
것을 전제로 했다. 막히지 않으면 가장 먼저 의심할 곳이다.
