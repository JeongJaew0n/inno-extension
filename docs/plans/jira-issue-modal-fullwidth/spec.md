# Jira 업무 모달 전체 폭 — 설계

- 상태: **구현 완료 · 실사용 확인(2026-09-15)**
- 작성일: 2026-09-15

## 1. 결론 먼저

**Jira에는 그 기능이 없다.** 모달을 넓히는 경로가 UI 어디에도 없다.

| 확인한 곳 | 결과 |
| --- | --- |
| 모달 우상단 버튼 4개 | 관찰·공유·`작업`·**사이드바로 전환**(= 더 좁아짐) |
| `작업(...)` 메뉴 17개 항목 | 전체 화면·확대·최대화 없음 |
| 전체 페이지 뷰 `/browse/` | 1680px로 더 넓지만 **보드를 벗어나고** 뷰포트 전체도 아님 |

**구현은 CSS 두 규칙이면 된다.** 실측으로 확인했다.

| 요소 | 현재 | 적용 후 |
| --- | --- | --- |
| 모달 | 1280 | **1920** (뷰포트 전체) |
| 본문 컬럼 | 928 | **1568** |

## 2. 왜 이렇게 되어 있나

모달 본체에 `width: 1280px`가 박혀 있다. `max-width`는 `1800px`이라 **여유가 있는데도 쓰지
않는다.** 바깥 컨테이너가 1800px에서 한 번 더 막는다.

```text
DIV role="presentation"                 1920   오버레이
└ DIV                    max-width:1800        ← 1차 제한
  └ SECTION role="dialog"  width:1280          ← 2차 제한 (본체)
```

둘 다 풀어야 뷰포트 전체가 된다.

## 3. 구현 방안

### 3.0 구현 결과 (2026-09-15)

폭만이 아니라 **상하 여백도 함께 푼다.** 사용자 요청으로 범위가 넓어졌다.

| 항목 | 기본 | 전체 크기 |
| --- | --- | --- |
| 모달 폭 (뷰포트 1920) | 1280 | **1920** |
| 모달 폭 (뷰포트 1512) | 1280 | **1512** |
| 모달 높이 (뷰포트 873) | 754 | **873** |
| 본문 컬럼 폭 | 928 | **1568** |
| 본문 레이아웃 높이 | 686 | **805** |

**폭과 높이를 막는 방식이 다르다.**

| 축 | 제한 방식 | 푸는 법 |
| --- | --- | --- |
| 폭 | 위치 컨테이너 `max-width` + 본체 `width` | 둘 다 `100vw` |
| 높이 | 위치 컨테이너 `position:absolute` + `top:60px; bottom:59px; max-height` | **오프셋을 0으로.** `height`만 늘리면 아래로 넘친다 |

본체 높이는 `100vh`로 준다. `100%`로 주면 컨테이너 높이가 확정되기 전에 계산돼 본문 전체
높이(실측 **15688px**)까지 늘어난다. 회귀 테스트로 막았다.

### 3.1 핵심 CSS

```css
/* 바깥 컨테이너와 모달 본체의 폭 제한을 함께 푼다. */
[data-testid*="issue-modal.modal-dialog"] {
  width: 100vw !important;
  max-width: 100vw !important;
}
```

`!important`가 필요하다. Jira가 원자 CSS 클래스로 폭을 지정한다.

### 3.2 선택자 규칙

**정정.** 조사 단계에서 `*=`(contains)로 적었으나, 정확한 `data-testid`는 셋이 각각 다르다.

| 요소 | `data-testid` | 대상 |
| --- | --- | --- |
| 오버레이 | `…modal-dialog--blanket` | **제외** (이미 전체) |
| 위치 컨테이너 | `…modal-dialog--positioner` | 폭·높이 해제 |
| 본체 | `…modal-dialog` | 폭·높이 해제 |

원자 클래스(`._1bsb1osq`)는 빌드마다 해시가 바뀌므로 쓰지 않는다. 회귀 테스트로 막았다.

### 3.3 토글 버튼

`사이드바로 전환` 버튼 **왼쪽**에 넣는다. 기존 버튼 그룹 순서를 바꾸지 않는다.

| 항목 | 내용 |
| --- | --- |
| 앵커 | `issue-view-fou…`(사이드바로 전환) 버튼의 부모 |
| 주입 방식 | Shadow DOM host. 다른 사이트 기능과 같은 방식 |
| 상태 | `전체 폭` ↔ `기본 폭` 토글 |
| 적용 | `<html>`에 `data-inno-jira-wide` 속성을 켜고 CSS가 그 속성 아래에서만 동작 |

속성 기반으로 하면 스타일 시트는 한 번만 주입하고 토글은 속성만 바꾸면 된다. 모달이 닫혔다
다시 열려도 스타일이 살아 있다.

```css
html[data-inno-jira-wide] [data-testid*="issue-modal.modal-dialog"] { ... }
```

### 3.4 설정 저장

| 항목 | 값 |
| --- | --- |
| 위치 | `chrome.storage.sync` (기존 설정 스키마에 옵션 추가) |
| 기본값 | **꺼짐** |
| 범위 | 사용자 단위. 켜두면 모달이 열릴 때마다 전체 폭 |

## 4. 쟁점

### 4.1 우측 필드 컬럼은 그대로 둔다 (결정됨)

모달을 넓혀도 우측 필드 컬럼은 **270px 그대로**이고 남는 폭을 본문이 전부 가져간다.

| 뷰 | 본문 | 우측 필드 |
| --- | --- | --- |
| 모달 (기본) | 928 | 270 |
| 모달 (전체 폭, 1920) | 1568 | 270 |
| 모달 (전체 폭, 1512) | 1160 | 270 |
| 전체 페이지 | 1041 | 553 |

**사용자 결정: 우측 컬럼은 건드리지 않는다. 본문만 늘어나면 된다.** Jira 내부 레이아웃 계산에
개입하지 않으므로 위험이 낮다.

### 4.2 본문 가독성

한 줄이 1568px면 긴 문단은 읽기 어렵다. 필요하면 본문 컬럼에만 `max-width`를 주는 절충안이
있다. 다만 그건 "전체 폭으로 보고 싶다"는 요구와 어긋날 수 있어 **사용자 판단이 필요하다.**

### 4.3 화면 폭별 이득이 다르다

| 뷰포트 | 모달 | 전체 폭 적용 후 | 본문 증가 |
| --- | --- | --- | --- |
| 1920 (외장) | 1280 | 1920 | 928 → **1568** (+69%) |
| 1512 (노트북) | 1280 | 1512 | 928 → **1160** (+25%) |

**모달 폭 1280은 뷰포트와 무관한 고정값이다.** 그래서 넓은 화면일수록 이득이 크다. 노트북에서도
효과는 있지만 절반 이하다.

### 4.4 백로그는 별도 대응이 필요하다

백로그에서는 **모달이 아예 없다.** 우측 도킹 `preview-panels.preview-panel`(400px)이 뜬다.
`issue-modal.modal-dialog`를 겨냥한 CSS는 백로그에서 **아무 효과가 없다.**

넓히는 것 자체는 같은 방식으로 된다(400 → 1134 실측, 되돌림 정확). 다만 성격이 다르다.

| 항목 | 보드 모달 | 백로그 패널 |
| --- | --- | --- |
| 목표 폭 | 뷰포트 전체 | 전체는 부적절 — 백로그 목록을 가린다 |
| 레이아웃 | 2단 | **1단** (넓혀도 2단으로 안 바뀜) |
| 전환 버튼 | 사이드바로 전환 있음 | 없음 |

**1차 범위는 보드 모달로 한정하고, 백로그는 별도 판단으로 미룬다.** 전체 폭이 아니라 "조금 더
넓게"가 맞는 화면이라 목표부터 다르다.

### 4.5 Jira 변경에 대한 취약성

`data-testid`는 Atlassian이 비교적 안정적으로 유지하지만 계약이 아니다. 바뀌면 CSS가 아무
효과를 내지 못한다. **깨져도 Jira 기본 동작이 그대로 남을 뿐 손상은 없다.** 퇴행이 아니다.
