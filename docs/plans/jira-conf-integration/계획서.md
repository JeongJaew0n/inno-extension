# jira-conf 기능 통합 계획서

- 상태: 분석 완료, 구현 승인 대기
- 작성일: 2026-08-11
- 대상 저장소: Inno Extension
- 분석 원본: `/Users/jjw/Downloads/jira-conf`
- 계획 식별자: `jira-conf-integration`

## 1. 목표

별도 Chrome 확장인 `jira-conf`의 Jira·Confluence 기능을 분석하고, Inno Extension의 서비스·기능·설정·runtime 구조를 깨뜨리지 않는 통합 방향을 확정한다.

이 계획의 완료 조건은 다음과 같다.

- 원본 기능을 사용자 가치 기준으로 분해한다.
- 현 프로젝트에 이미 있는 기능과 중복되는 부분을 식별한다.
- 추가 권한, 인증 정보, 외부 API, 비공식 Atlassian API 사용에 따른 보안·운영 영향을 드러낸다.
- 한 번에 전체 코드를 옮기지 않고 검증 가능한 단계로 통합 순서를 정한다.
- 구현 전에 사용자 승인이 필요한 제품 결정을 명확히 남긴다.

## 2. 분석 결론 요약

`jira-conf`는 단순한 Jira 복사 버튼 모음이 아니다. 핵심은 Confluence ADF(Atlas Document Format)를 REST API로 읽고 쓰면서 Markdown과 양방향 변환하고, Atlassian Media Platform을 통해 이미지까지 올리고 내려받는 도구다.

원본을 통째로 합치면 다음 변화가 동시에 발생한다.

- `storage`만 사용하던 확장에 Atlassian host 접근과 다운로드 권한이 추가된다.
- 현재 DOM 기반·무인증 원칙과 달리 Atlassian 이메일/API 토큰을 로컬에 저장한다.
- Vanilla TypeScript Popup에 React 기반 680줄 단일 화면을 얹거나 Popup 전체를 재작성해야 한다.
- `marked`, React, `@atlaskit/media-client` 및 그 하위 의존성이 추가되어 번들과 공급망 범위가 크게 늘어난다.
- 공식 REST API뿐 아니라 비공식 GraphQL, `_edge/tenant_info`, 설치된 Forge 앱의 하드코딩된 extension key에 의존하게 된다.
- Confluence 문서를 읽는 기능뿐 아니라 원격 문서를 수정하는 기능이 생긴다.

따라서 권장 방향은 **원본의 사용자 기능과 순수 변환 로직은 선별 이관하되, UI·설정·runtime은 Inno Extension 방식으로 다시 구성하는 것**이다.

## 3. 원본 기능 목록

### 3.1 Jira 업무 링크 복사

원본은 `/browse/{업무번호}`, `selectedIssue`, `/issues/{업무번호}`에서 업무 번호를 읽고 화면의 가장 긴 가시 `h1`을 제목으로 추정한다. 제목 옆에 다음 두 버튼을 표시한다.

- Markdown 복사: `[NPT-38](정규 URL) 업무 제목`
- HTML 복사: 업무 번호를 HTML 링크로 쓰고 제목을 뒤에 붙인다. plain text fallback은 Markdown 문자열이다.

현 프로젝트의 `issueLinkCopy`와 대부분 중복된다. 현 기능은 모든 Jira 보드의 선택 업무 dialog를 지원하며 다음 두 동작을 이미 제공한다.

- `업무 링크 복사`
- `업무 링크 복사(제목포함)`

따라서 새 기능을 병렬로 추가하지 않는다. 필요하다면 기존 `issueLinkCopy`에 직접 업무 조회 화면(`/browse/{업무번호}`) 지원을 확장하고, Markdown 전용 출력은 별도 제품 결정 후 옵션 또는 별도 버튼으로 추가한다.

### 3.2 Confluence 문서 → Markdown

원본은 Confluence v2 REST API로 ADF 본문을 읽고 Markdown으로 변환한다.

지원 범위는 제목, 문단, 인용, 목록, 작업 목록, 표, 코드 블록, 링크, 강조, 펼치기, 외부 이미지, 업로드 이미지 참조다. 업로드 이미지는 Markdown에 `image/<파일명>` 경로를 만들고 호출자가 별도로 다운로드한다.

현 프로젝트의 `pageMarkdownCopy`는 렌더링된 DOM을 변환하므로 인증 없이 한 번에 복사할 수 있다. 두 방식은 경쟁 관계가 아니라 목적이 다르다.

- DOM 복사: 무설정, 현재 화면 기준, 한 번 클릭, UI 변경에 취약
- ADF 내보내기: API 토큰 필요, 원본 문서 모델 기준, 더 안정적인 구조, 일부 매크로 손실 가능

권장안은 기존 DOM 복사를 유지하고, API 기반 고정밀 내보내기를 별도 기능으로 추가하는 것이다.

### 3.3 Markdown → Confluence 문서 끝에 삽입

원본은 사용자가 붙여넣거나 `.md` 파일에서 읽은 Markdown을 ADF 노드로 변환한 뒤 현재 페이지 본문 끝에 추가한다. 새 페이지를 만드는 코드는 확인되지 않았다.

지원 범위는 GFM 표, 목록, 작업 목록, 코드 블록, 기본 인라인 서식, 펼치기, 외부 이미지, 선택한 로컬 이미지 업로드다. 원본 HTML은 생략하고 경고한다.

이 기능은 원격 문서를 실제로 수정하므로 다음 보호 장치가 필요하다.

- 대상 페이지 ID·제목·상태를 실행 전에 명시한다.
- 추가될 내용의 미리보기 또는 최소한 요약을 제공한다.
- `페이지 끝에 추가`임을 버튼과 확인 화면에 표시한다.
- 현재 버전 불일치·409 충돌은 덮어쓰지 않고 중단한다.
- 성공 후 페이지 새로고침과 결과 확인 경로를 제공한다.
- 작성 중 편집기와 동시에 실행하지 않도록 안내한다.

### 3.4 이미지 업로드·다운로드

원본은 `@atlaskit/media-client`를 사용한다. Confluence 내부 GraphQL에서 페이지 범위 Media Platform 토큰을 받고, 로그인 세션 쿠키로 인증한다. 이 GraphQL은 Popup origin을 거부해 Confluence content script가 대신 호출하고 결과를 Popup으로 전달한다.

로컬 이미지 매칭은 Markdown 경로의 basename과 선택 파일명을 비교하므로 동일 파일명 충돌 가능성이 있다. 다운로드는 `.md` 파일과 `image/` 하위 경로를 만들기 위해 `chrome.downloads`를 사용한다.

공식·안정 API만으로 구성된 기능이 아니므로 텍스트 통합 이후 별도 단계에서 실제 사내 tenant로 검증해야 한다.

### 3.5 Mermaid 라이브 렌더링

원본은 Mermaid fenced code block을 접힌 코드 영역으로 보존하고, 그 앞에 설치된 Forge Mermaid 앱의 ADF extension 노드를 삽입한다.

extension key는 특정 사이트에서 캡처한 하드코딩 값이며 코드 주석도 비공식·사이트 종속·변경 가능성을 인정한다. 사용자 account ID, cloud ID, page ID/version, space ID/key가 추가로 필요하다.

이 기능은 기본 통합 범위에서 제외하고 실험 기능으로 격리한다. 현재 tenant에서 extension key와 ADF payload를 재검증한 뒤에만 활성화한다.

### 3.6 디버그 도구

원본 Popup은 Confluence storage XML과 ADF JSON 원문 조회 기능을 일반 설정 화면에 노출한다. 이는 최종 사용자 기능보다 개발·분석 도구에 가깝다.

초기 통합에는 포함하지 않는다. 필요하면 개발 빌드 전용 도구 또는 별도 진단 페이지로 분리한다.

## 4. 원본 문서와 코드의 불일치

원본 README는 `src/publish`에서 새 페이지 생성·업데이트를 지원하고 storage XHTML로 반영한다고 설명한다. 실제 소스에는 `src/publish`가 없고, Popup은 현재 페이지를 v2 ADF로 조회한 뒤 본문 끝에 노드를 추가해 v2 ADF로 업데이트한다. 새 페이지 생성 API도 확인되지 않았다.

따라서 README를 기능 정본으로 사용하지 않고 실제 소스 동작을 기준으로 통합한다.

## 5. 통합 원칙

### 5.1 기존 기능을 보존한다

- 기존 `본문 Markdown 복사`는 API 기능 도입 후에도 기본 ON으로 유지한다.
- 기존 Jira 복사 기능을 중복 주입하지 않는다.
- 기존 서비스 전체 기능 gate와 기능별 lifecycle을 그대로 사용한다.
- 기존 설정 migration과 이미 저장된 사용자 설정을 보존한다.

### 5.2 UI 프레임워크를 바꾸지 않는다

원본 React Popup 전체를 이식하지 않는다. 현재 Popup의 서비스 → 기능 → 상세 설정 구조에 필요한 화면만 추가한다. React 도입 여부는 이 통합과 분리된 아키텍처 결정으로 남긴다.

### 5.3 인증 정보와 일반 설정을 분리한다

- 기능 ON/OFF와 비밀이 아닌 옵션은 기존 `chrome.storage.sync`에 둔다.
- Atlassian 이메일/API 토큰은 전용 key로 `chrome.storage.local`에만 저장한다.
- `storage.local`은 암호화된 비밀 저장소가 아님을 UI에 명시한다.
- 가능한 경우 `chrome.storage.local.setAccessLevel({ accessLevel: "TRUSTED_CONTEXTS" })`로 content script의 접근을 차단한다.
- API 토큰은 로그·오류·spec·테스트 fixture에 기록하지 않는다.
- 토큰 삭제 기능과 인증 확인 피드백을 제공한다.

### 5.4 네트워크 접근을 한 경계로 모은다

공식 REST API 요청은 background service worker의 Confluence API broker로 모으는 안을 우선한다. Popup과 content feature는 typed message로 요청하고, broker는 sender·origin·page ID·payload를 검증한다.

브라우저 세션과 페이지 origin이 필요한 Media Platform 토큰 조회만 Confluence content script에 남긴다. 이 경로는 메시지 type을 명시하고 Confluence origin과 page ID를 검증한다.

### 5.5 권한은 단계별 최소화한다

권장 manifest 방향은 다음과 같다.

| 권한 | 용도 | 결정 |
| --- | --- | --- |
| `storage` | 기존 설정과 로컬 인증 정보 | 유지 |
| 정확한 Atlassian host permission | Popup/background의 Confluence REST 호출 | API 기능 도입 시 추가 |
| `activeTab` | 활성 탭 URL/ID 접근 | 정확한 host permission만으로 충분한지 검증 후 결정 |
| `scripting` | 원본에 선언됐지만 사용처 없음 | 추가하지 않음 |
| `downloads` | `.md`와 `image/` 파일 저장 | 파일 다운로드 단계에서만 추가, 가능하면 optional permission |
| `*://*.atlassian.net/*` | 모든 Atlassian tenant 접근 | 사용하지 않음 |

지원 origin은 현재 제품 범위인 `https://pms-innogrid.atlassian.net/*`로 제한한다.

## 6. 제안 기능 구조

### Jira 서비스

- `issueLinkCopy` 유지
  - 기존 보드 선택 업무 지원
  - 승인 시 `/browse/{업무번호}` 직접 조회 화면 지원 추가
  - 승인 시 Markdown 출력 방식 추가

### Confluence 서비스

- `pageMarkdownCopy` 유지
  - 현재 DOM 기반 한 번 클릭 복사
- `pageMarkdownExport` 신규
  - ADF API 기반 Markdown 클립보드 복사
  - 후속 단계에서 `.md` 및 이미지 다운로드
- `pageMarkdownAppend` 신규
  - Markdown 입력·파일 읽기
  - ADF 변환 미리보기와 경고
  - 현재 페이지 끝에 추가

이미지와 Mermaid는 독립된 최상위 기능보다 export/append의 선택 capability로 다룬다. 디버그 원문 조회는 제품 기능 목록에 넣지 않는다.

## 7. 단계별 구현 계획

### 단계 0. 제품·보안 결정 확정

- 이 문서의 열린 결정을 사용자와 확정한다.
- `spec/product-overview.md`의 DOM 우선·API/토큰 비사용 원칙을 어떻게 수정할지 합의한다.
- API 토큰 저장 안내와 권한 증가를 제품 정책으로 승인한다.
- 원본 코드 직접 이관에 필요한 소유권·출처를 확인한다.

완료 기준: 구현 범위, 기본값, 인증 저장, 권한, Mermaid 포함 여부가 문서로 확정된다.

### 단계 1. 순수 변환 계층과 회귀 fixture

- ADF 공통 type을 플랫폼 독립 모듈로 정리한다.
- `adfToMarkdown`과 `markdownToAdfNodes`를 UI·Chrome API 없이 실행 가능하게 이관한다.
- 실제 사내 콘텐츠는 익명화한 fixture만 사용한다.
- 제목, 목록, 작업 목록, 표, 코드, 링크, 펼치기, 이미지 참조, 미지원 노드 fallback을 단위 테스트한다.
- 원본 HTML 생략과 손실 경고를 테스트한다.

완료 기준: 네트워크와 Chrome 없이 양방향 변환 테스트가 통과한다.

### 단계 2. Jira 중복 기능 정리

- 기존 Jira route parser에 직접 업무 조회 URL을 추가한다.
- 현재 dialog selector 우선 전략과 직접 조회 화면의 heading 탐색 전략을 분리한다.
- 현재 버튼/클립보드 계약을 유지한다.
- Markdown 출력 추가가 승인된 경우에만 별도 동작을 추가한다.

완료 기준: 보드 기능 회귀 없이 직접 업무 조회 화면 적용 조건과 출력이 테스트된다.

### 단계 3. Confluence 인증·API 기반

- 전용 local credential repository를 추가한다.
- background API broker와 요청/응답 contract를 추가한다.
- 페이지 ID parser, current/draft ADF 조회, current/draft 업데이트, 인증 오류, 충돌 오류를 테스트한다.
- exact host permission을 추가하고 manifest/catalog origin 일치 검사를 갱신한다.
- Popup Confluence 서비스 설정에 저장·삭제·인증 확인 피드백을 추가한다.

완료 기준: 테스트 tenant의 읽기 전용 페이지 조회가 성공하고 토큰이 sync 저장소·로그·content script에 노출되지 않는다.

### 단계 4. API 기반 Markdown 내보내기

- `pageMarkdownExport`를 기능 catalog와 기본 설정에 등록한다.
- 먼저 텍스트 클립보드 복사만 제공한다.
- 미지원 ADF node와 이미지 미포함 상태를 사용자에게 경고한다.
- 기존 DOM 기반 복사 버튼과 이름·설명을 구분한다.

완료 기준: 같은 문서를 DOM 방식과 ADF 방식으로 각각 복사할 수 있고, 기존 기본 동작이 변하지 않는다.

### 단계 5. Markdown 본문 추가

- `pageMarkdownAppend`를 등록한다.
- Popup 기능 상세에서 Markdown 붙여넣기와 `.md` 파일 입력을 제공한다.
- 대상 문서, 추가 위치, 변환 경고를 실행 전에 보여준다.
- 텍스트와 외부 이미지 URL만 우선 지원한다.
- version conflict를 재시도나 덮어쓰기로 숨기지 않고 중단한다.

완료 기준: current와 draft에 대한 실제 검증 결과가 기록되고, 실패 시 원본 문서를 덮어쓰지 않는다.

### 단계 6. 로컬 이미지 업로드·다운로드

- Media Platform token message를 별도 capability로 추가한다.
- `@atlaskit/media-client` 도입 전 번들·라이선스·유지보수 영향을 다시 확인한다.
- basename 단독 매칭을 개선해 상대 경로 또는 사용자 선택으로 충돌을 해소한다.
- 업로드 완료 상태까지 subscription을 유지하고 취소·부분 실패를 처리한다.
- 다운로드 기능에만 `downloads` 권한을 연결한다.

완료 기준: 이미지 성공, 같은 이름 충돌, 일부 실패, 로그인 세션 만료를 실제 tenant에서 확인한다.

### 단계 7. Mermaid 실험 기능

- 설치된 Mermaid Forge 앱의 현재 extension key와 ADF payload를 재수집·익명화해 검증한다.
- hardcoded key를 core 변환기에서 분리하고 site capability 설정으로 이동한다.
- 지원 불가 시 Mermaid source fence만 보존한다.
- 기본 OFF 실험 기능으로만 공개한다.

완료 기준: 실패해도 본문 삽입은 성공하고 Mermaid source가 손실되지 않는다.

### 단계 8. 문서·배포 검증

- 기능별 정본 spec과 제품 개요·용어사전을 갱신한다.
- README 기능·권한·설정·보안 안내를 갱신한다.
- typecheck, unit test, production build, package 검사를 실행한다.
- 실제 로그인된 Jira/Confluence에서 수동 smoke test를 수행한다.
- 기존 아마란스/Jira/Confluence 기능 회귀를 확인한다.

완료 기준: 자동 검증과 수동 검증 결과가 남고 배포 산출물이 생성된다.

## 8. 테스트 전략

### 자동 테스트

- URL parsing: Jira board/direct issue, Confluence view/edit/draft
- Clipboard contract: 기존 HTML/plain 결과와 선택적 Markdown 결과
- ADF → Markdown fixture: 표, 중첩 목록, task, code, expand, image, unknown node
- Markdown → ADF fixture: GFM, HTML omission warning, external/local image
- API broker: 인증 오류, 404 current→draft fallback, 409/version conflict, malformed response
- storage: sync 설정 migration, local credential 격리·삭제
- message validation: 잘못된 sender/origin/type/page ID 거절
- manifest: exact origin, 미사용 `scripting` 부재, 권한 기대값

### 수동 검증

- Jira 보드 선택 업무와 `/browse/{업무번호}`
- Confluence published page와 draft
- 큰 표, 코드 블록, 펼치기, 미지원 매크로가 섞인 문서
- API 토큰 오류·만료, 로그인 세션 만료
- 문서 동시 편집 중 version conflict
- 이미지 업로드·다운로드와 동일 파일명 충돌
- 확장 재로드·SPA 이동·기능/서비스 OFF cleanup

## 10. 구현 전 확정이 필요한 결정

다음은 현재 권장안이며 사용자 승인 전에는 구현하지 않는다.

1. 기존 DOM 기반 `본문 Markdown 복사`를 유지하고 API 기반 내보내기를 별도 기능으로 추가한다.
2. Jira는 기존 `업무 링크 복사`에 직접 업무 조회 화면만 확장하며, Markdown 버튼은 별도 승인한다.
3. Confluence 쓰기 기능은 `현재 페이지 끝에 추가`만 1차 범위로 하고 새 페이지 생성은 제외한다.
4. API 토큰을 `storage.local`에 저장하는 방식을 수용한다.
5. Atlassian host permission은 사내 tenant 한 곳으로 제한한다.
6. React와 options page는 이식하지 않고 현재 Popup 구조를 확장한다.
7. 이미지 기능은 텍스트 기능 이후 별도 단계로 도입한다.
8. Mermaid 라이브 렌더링은 기본 통합에서 제외하고 실험 기능으로 둔다.
9. storage XML/ADF JSON 디버그 화면은 일반 사용자 기능에서 제외한다.

## 11. 이번 계획에서 하지 않는 일

- 아직 통합 코드를 수정하지 않는다.
- API 토큰을 입력하거나 실제 Confluence 문서를 변경하지 않는다.
- manifest 권한을 추가하지 않는다.
- 원본 `node_modules`, `dist`, React UI를 복사하지 않는다.
- 새 Confluence 페이지 생성 기능이 있다고 가정하지 않는다.
