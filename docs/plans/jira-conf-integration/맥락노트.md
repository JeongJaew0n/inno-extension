# jira-conf 기능 통합 맥락노트

- 최종 갱신일: 2026-08-11
- 현재 단계: 원본 분석 완료, 구현 전 결정 승인 대기
- 다음 작업 시작점: `계획서.md`의 10장 결정 확인 후 `체크리스트.md` 단계 0부터 진행

## 1. 사용자 요청

별도 확장 프로젝트 `jira-conf`에 있는 기능을 분석해 Inno Extension에 합칠 예정이다. 이번 요청은 분석과 구현 계획 작성까지이며, 실제 통합 구현은 계획 검토 이후 진행한다.

명시적으로 `ai-memory-plan`을 사용했으므로 이 폴더의 계획서·맥락노트·체크리스트를 다음 세션에서도 작업 정본으로 사용한다. 제품의 최종 행동 계약은 구현 시 `spec/`에 별도로 반영해야 한다.

## 2. 현 Inno Extension 기준선

### 제품 구조

- Manifest V3, Vite/CRXJS, Vanilla TypeScript
- 서비스: 아마란스, Jira, Confluence
- 서비스별 content entry와 기능별 `FeatureRuntime`
- 사이트당 중앙 runtime이 SPA 변화와 storage 변경을 관찰하고 기능별 `reconcile()`/`dispose()`를 관리
- Popup은 서비스 목록 → 서비스 상세 → 기능 상세 구조
- 기능 ON/OFF와 옵션은 versioned `chrome.storage.sync` 설정에 저장
- 현재 runtime dependency 없음

### 현재 manifest

- permission: `storage`
- content script origin:
  - `https://gw.innogrid.com/*`
  - `https://pms-innogrid.atlassian.net/jira/*`
  - `https://pms-innogrid.atlassian.net/wiki/*`
- 별도 `host_permissions`, `downloads`, `scripting`, `activeTab` 없음

### 겹치는 현재 기능

- Jira `issueLinkCopy`
  - 모든 Jira 보드 기본 화면의 선택 업무 dialog 지원
  - `업무 링크 복사`, `업무 링크 복사(제목포함)` 제공
  - HTML link + plain text fallback
  - API 없이 URL과 DOM 사용
- Confluence `pageMarkdownCopy`
  - 조회 화면의 렌더링된 본문 DOM을 Markdown으로 변환
  - 제목·작성자·댓글 제외
  - API·토큰·세션 쿠키 없이 동작

### 현재 제품 원칙과 충돌

`spec/product-overview.md`와 `spec/features/confluence-page-markdown-copy.md`는 다음을 현재 원칙/비목표로 명시한다.

- DOM 기반 상호작용 우선
- 인증 정보와 사내 API를 직접 다루지 않음
- 토큰·세션 쿠키를 직접 사용하지 않음
- 사이트 권한을 실제 지원 origin으로 제한
- Popup은 현재 규모에서 Vanilla TypeScript 유지

`jira-conf`의 API 토큰 저장, REST write, 내부 GraphQL, Atlaskit Media Client는 이 원칙의 단순한 구현 상세가 아니라 제품·보안 경계 변경이다. 구현 전에 spec 결정이 필요하다.

## 3. 분석 원본 요약

### 프로젝트 상태

- 이름/버전: `jira-conf-extension` 0.1.0
- Manifest V3, Vite + React + TypeScript
- Git 저장소 아님: commit history와 원본 provenance를 해당 폴더만으로 확인할 수 없음
- 테스트 파일과 test script 없음
- scripts: dev, build, preview, lint, typecheck
- runtime dependencies:
  - React 18
  - `marked` 18
  - `@atlaskit/media-client` 37.2.25
- 분석 시점 산출물 규모:
  - `dist` 약 728KB
  - `node_modules` 약 246MB
  - 가장 큰 build chunk 약 417KB

규모 값은 현재 원본의 스냅샷이며 통합 후 예상값을 뜻하지 않는다.

### manifest 권한

- `storage`
- `activeTab`
- `scripting`
- `downloads`
- host permission: `*://*.atlassian.net/*`

소스 검색 결과 `chrome.scripting` 사용처는 확인되지 않았다. `downloads`는 `.md`와 `image/` 파일 저장에 사용된다. 활성 탭 URL·ID 조회와 reload에 `chrome.tabs`가 사용된다. wildcard host permission은 현 제품 범위보다 넓다.

## 4. 원본 데이터 흐름

### Jira 복사

```text
현재 URL + 가시 h1
  → 업무 번호/제목 추출
  → MD 또는 HTML payload 생성
  → Clipboard API
```

특징:

- `/browse`, `selectedIssue`, `/issues` URL 지원
- 가시 `h1` 중 텍스트가 가장 긴 요소를 제목으로 선택하는 heuristic
- body 전체 MutationObserver + requestAnimationFrame
- sync storage의 단일 `copyButtonsEnabled` 사용

통합 시 주의:

- 기존 `createSiteRuntime`와 observer를 공유해야 한다.
- 기존 버튼을 두고 원본 버튼을 추가하면 중복 UX와 clipboard 계약 충돌이 생긴다.
- 가장 긴 `h1` heuristic은 Jira DOM이 바뀔 때 잘못된 제목을 고를 수 있으므로 안정 selector 우선, heuristic fallback 순서가 필요하다.

### Confluence ADF 읽기

```text
Popup 사용자 클릭
  → local storage에서 email/API token 조회
  → Confluence v2 REST API로 page ADF 조회
  → ADF → Markdown 변환
  → clipboard 또는 .md 다운로드
```

current 페이지 조회가 404이면 `status=draft`로 재시도한다.

### Confluence ADF 쓰기

```text
Markdown 입력/.md 파일
  → 현재 page ADF + version 조회
  → Markdown → ADF nodes
  → 기존 document.content 끝에 append
  → v2 REST PUT
```

- current 상태는 version을 1 증가시킨다.
- draft 상태는 원본 version을 유지한다.
- 페이지 전체를 새 ADF document로 PUT하므로 version 충돌과 동시 편집 보호가 중요하다.
- 코드상 새 페이지 create는 없다.

### 이미지 업로드

```text
Markdown 이미지 경로 + 사용자가 선택한 이미지 파일
  → basename으로 파일 매칭
  → Confluence content script가 내부 GraphQL 호출
  → browser session cookie로 Media Platform token 수신
  → @atlaskit/media-client upload
  → fileId/collection을 ADF media node에 기록
```

주의:

- 내부 GraphQL은 공식 계약이 아니며 사이트 origin/CORS 동작에 의존한다.
- 업로드 subscription은 `uploading` 이후 완료 상태까지 유지해야 한다. 일찍 unsubscribe하면 fileId만 예약되고 실제 bytes 전송이 중단될 수 있다는 원본 주석과 처리 코드가 있다.
- basename 매칭은 서로 다른 폴더의 동일 파일명을 구분하지 못한다.

### 이미지 다운로드

```text
ADF media node
  → Markdown image/<파일명> 참조 생성
  → Media Platform token 조회
  → media-client로 binary 조회
  → chrome.downloads로 .md와 image/ 경로 저장
```

클립보드 복사 모드에서는 이미지 bytes가 포함되지 않고 경고만 제공한다.

### Mermaid

```text
mermaid fence
  → 접힌 expand 안에 source codeBlock 보존
  → Forge extension ADF node를 앞에 삽입
```

필수 context:

- accountId
- cloudId
- pageId/pageVersion
- spaceId/spaceKey
- 특정 tenant의 Mermaid Forge extension key

현재 key는 원본 소스에 하드코딩되어 있고 비공식·사이트 종속이다. 통합 core에 넣지 않는다.

## 5. 변환기 지원 범위

### Markdown → ADF

지원:

- heading, paragraph, blockquote, horizontal rule
- bullet/ordered/task list
- GFM table
- fenced code block
- strong, emphasis, strike, inline code, link, hard break
- `<details><summary>` 형태의 expand
- 외부 HTTP 이미지
- 사전 업로드된 local image의 media node
- Mermaid source 보존

손실/경고:

- raw HTML block 생략
- inline HTML 생략
- 문단 중간 이미지 link 대체
- 매칭되지 않은 local image 자리표시자 대체

### ADF → Markdown

지원:

- heading, paragraph, rule, blockquote
- bullet/ordered/task list
- table
- codeBlock
- expand와 Mermaid round-trip
- external/uploaded media
- strong, em, strike, code, link

fallback:

- 알 수 없는 block은 자식 content를 재귀 변환
- extension node는 생략
- unsupported macro의 고유 semantics는 손실될 수 있음

## 6. 코드 품질 관찰

### 재사용 가치가 높은 부분

- page ID URL parser
- current/draft ADF fetch/update 분기
- ADF ↔ Markdown 순수 변환 로직
- 변환 warning 수집 방식
- 이미지 파일명 sanitize와 중복 파일명 처리
- media upload 완료를 기다리는 subscription 처리 지식

### 그대로 이식하지 않을 부분

- React Popup/App.tsx 전체
- options page 중복 설정 UI
- 단일 `copyButtonsEnabled` 설정 schema
- 별도 body MutationObserver를 가진 Jira content script
- wildcard Atlassian host permission
- 미사용 `scripting` permission
- 일반 사용자 화면의 storage XML/ADF debug viewer
- core 변환기에 들어간 hardcoded Mermaid extension key
- basename만 사용하는 이미지 매칭

### 원본 문서 불일치

README는 존재하지 않는 `src/publish`, 새 페이지 생성, storage XHTML write를 설명한다. 실제 소스는 Popup에서 현재 페이지를 ADF v2로 읽고 append/update한다. 분석과 이관은 소스를 기준으로 한다.

## 7. 권장 아키텍처 경계

```text
Popup feature detail/actions
  ├─ 기존 sync settings repository
  ├─ local credential repository (token 전용)
  └─ typed runtime messages
       └─ background Confluence API broker
            ├─ v2 page read/write
            ├─ v1 user/space 보조 조회
            └─ 응답/오류 normalization

Confluence site runtime
  ├─ 기존 DOM pageMarkdownCopy
  └─ media token message handler (이미지 단계에서만)

순수 shared modules
  ├─ page URL parser
  ├─ ADF types
  ├─ ADF → Markdown
  └─ Markdown → ADF
```

원칙:

- credential을 content script에 전달하지 않는다.
- pure converter는 Chrome API와 fetch를 import하지 않는다.
- API client는 UI state를 다루지 않는다.
- 기존 site runtime 외에 DOM observer를 추가하지 않는다.
- 원격 write는 사용자의 명시적 action과 대상 확인 뒤에만 실행한다.

## 8. 결정 기록

### 확정된 분석 판단

- 원본은 Git 저장소가 아니며 테스트가 없다.
- 원본 Jira 기능은 현 `issueLinkCopy`와 중복된다.
- 원본 Confluence 기능은 DOM 복사의 단순 대체가 아니라 인증 기반 고정밀 export/append 도구다.
- 원본에 새 Confluence 페이지 생성 기능은 없다.
- `scripting` permission은 원본 source에서 사용되지 않는다.
- Mermaid와 Media Platform은 비공식/사이트 종속 의존성을 가진다.

### 권장하지만 승인되지 않은 결정

- DOM 복사 유지 + API export 별도 기능
- 현재 Popup/Vanilla TS 유지
- exact company tenant host permission만 사용
- token은 local 전용 repository + trusted context 제한
- 이미지와 Mermaid를 후속 단계로 분리
- debug viewer 제외

## 9. 작업 시 반드시 보존할 불변조건

- 기존 아마란스/Jira/Confluence 기능이 계속 동작한다.
- 서비스 전체 OFF는 하위 설정값을 삭제하지 않는다.
- 기존 `extensionSettings` migration을 깨뜨리지 않는다.
- token을 sync storage, 로그, 문서, fixture에 남기지 않는다.
- 원격 문서를 사용자 클릭 없이 수정하지 않는다.
- version conflict에서 묵시적으로 재조회·덮어쓰기하지 않는다.
- 공식 지원 origin 밖으로 권한을 넓히지 않는다.
- API 기능 실패가 기존 DOM 기반 복사 기능을 비활성화하지 않는다.

## 10. 다음 세션 인수인계

1. `계획서.md` 10장의 9개 결정을 사용자에게 검토받는다.
2. 승인이 끝나기 전에는 source integration을 시작하지 않는다.
3. 구현 시작 시 현재 worktree의 기존 변경을 먼저 확인하고 다른 작업을 덮어쓰지 않는다.
4. `체크리스트.md`에서 한 번에 1~2개 항목만 진행 중으로 잡는다.
5. 단계 1의 pure converter와 fixture부터 시작한다. API·권한·token UI를 한 커밋에 섞지 않는다.
6. 제품 경계 변경을 `spec/`에 먼저 반영하거나 구현과 같은 변경 묶음에서 정합성을 유지한다.
