# 백로그 슬래시 템플릿 — 기술 검토와 설계

- 상태: **구현 완료 · 사용자 확인 완료(2026-09-16)**
- 작성일: 2026-09-16

## 1. 결론 먼저

**가능하다. 그리고 이 저장소가 지금까지 한 것들 중 난이도가 낮은 편이다.**

세 가지 관문을 모두 실측으로 통과했다.

| 관문 | 결과 |
| --- | --- |
| 입력창이 다루기 쉬운가 | **평범한 `<input>`.** ProseMirror가 아니다 |
| 값을 넣으면 React가 받는가 | **받는다.** `__reactProps.value`가 주입값과 일치 |
| `/`가 Jira와 충돌하는가 | **안 한다.** Jira가 이 입력창에서 `/`에 아무것도 걸지 않았다 |

Confluence Mermaid 기능은 MAIN world 브리지·ProseMirror transaction·3초 검증 타임아웃까지
필요했다. 이번 건은 **DOM 이벤트와 `<input>` 값 주입만으로 끝난다.**

## 2. 동작 계약

### 트리거

입력값이 `/`로 시작하고, **커서가 그 토큰 안에 있을 때** 목록을 띄운다.

```text
/              → 전부:  [공통] · [DevOpsit][BE] · [DevOpsit]
/Dev           → 걸러짐: [DevOpsit][BE] · [DevOpsit]
/dev           → 대소문자 무시로 같은 결과
[공통] /Dev    → 트리거하지 않는다 (아래 참조)
```

**첫 글자가 `/`일 때만** 트리거한다. 문장 중간의 `/`는 경로·날짜 표기에 흔하다
(`src/sites/jira`, `9/16`). 중간 트리거를 허용하면 정상 입력을 방해한다.

### 선택과 삽입

| 키 | 동작 |
| --- | --- |
| `↓` `↑` | 항목 이동 |
| `Enter` `Tab` | 선택한 항목 삽입 |
| `Esc` | 목록 닫기. 입력값은 그대로 |
| 그 외 타이핑 | 필터 갱신 |

삽입하면 `/Dev` 토큰을 템플릿 문자열로 **치환**하고 커서를 끝으로 보낸다. 뒤에 공백 하나를
붙여 바로 이어 쓸 수 있게 한다.

```text
/Dev  →  [DevOpsit][BE] ▌
```

### Enter 충돌이 핵심 쟁점

이 입력창의 `Enter`는 **이슈 생성**이다. 목록이 열린 상태의 `Enter`는 삽입이어야 하고,
**Jira로 전파되면 안 된다.**

```js
if (listOpen) {
  event.preventDefault();
  event.stopPropagation();   // Jira의 onKeyDown 에 닿지 않게
  insertSelected();
}
```

`stopPropagation`만으로 부족하면 `capture` 단계에서 잡는다. 목록이 닫혀 있을 때는 **아무것도
하지 않는다.** 평소 Enter 동작을 건드리면 안 된다.

### IME

한글 입력 중에는 `compositionstart`~`compositionend` 사이에 키 이벤트가 정상적이지 않다.
조합 중에는 트리거·필터를 갱신하지 않고, `compositionend` 후에 다시 계산한다.

`event.isComposing`과 `keyCode === 229`를 함께 확인한다.

## 3. 값 주입 방법

controlled input이라 DOM 값만 바꾸면 다음 렌더에서 되돌아갈 수 있다. **native setter를 통해
넣고 `input` 이벤트를 쏜다.**

```ts
const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value')!.set!;
setter.call(input, next);
input.dispatchEvent(new Event('input', { bubbles: true }));
input.setSelectionRange(next.length, next.length);
```

실측에서 순진한 `input.value = ...`도 통했지만 React 구현에 기대는 동작이다. **표준 우회를
쓴다.**

## 4. 템플릿은 어디에 두나

| 안 | 내용 | 평가 |
| --- | --- | --- |
| **A** | 코드에 상수로 박는다 | 가장 단순. 바꾸려면 릴리즈해야 함 |
| **B** | Popup 기능 상세에서 편집, `chrome.storage.sync` 저장 | **권장.** 사용자마다 다르고 자주 바뀐다 |

**B를 권한다.** 프로젝트·팀마다 접두사가 다르고, 새 접두사가 생길 때마다 릴리즈하는 것은
비용이 맞지 않는다. `titleAutofill`이 이미 Popup에서 문구를 저장하는 선례다.

기본값으로 요청하신 세 개를 넣어 켜자마자 쓸 수 있게 한다.

```
[공통]
[DevOpsit][BE]
[DevOpsit]
```

### 필터 규칙

입력한 토큰이 항목에 **포함**되면 보여준다. 대소문자는 무시한다. `[`·`]`는 무시하고 비교해
`/Dev`가 `[DevOpsit]`에 걸리게 한다.

## 5. UI

Shadow DOM host에 목록을 그려 입력창 아래에 띄운다. 다른 기능과 같은 방식이다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 입력창 기준 `position: fixed`로 아래. 화면 아래가 좁으면 위로 뒤집는다 |
| 너비 | 입력창 너비를 따르되 최소값을 둔다 |
| 강조 | 선택 항목에 배경색. 마우스 hover로도 선택 이동 |
| 접근성 | `role="listbox"` / `role="option"`, `aria-activedescendant` |

목록은 **입력창이 사라지면 함께 닫는다.** 인라인 생성은 Escape로 닫히므로 그 경우도 처리한다.

## 6. 적용 범위

| 화면 | 포함 | 비고 |
| --- | --- | --- |
| 백로그 인라인 생성 | **포함** | 유일한 대상 |
| 스프린트 영역 | **해당 없음** | **인라인 생성이 존재하지 않는다.** 9절 참조 |
| 보드 인라인 생성 | 미정 | 존재 여부 미확인 |
| 업무 상세의 제목 편집 | **제외** | 다른 컴포넌트다. 범위를 넓히지 않는다 |

앵커는 `input[aria-label="Work item summary"]`로 잡고, 카드 리스트 컨테이너 안에 있는 것만
대상으로 한다. 여러 개가 동시에 열리지는 않지만 방어적으로 처리한다.

## 7. 위험

| 위험 | 완화 |
| --- | --- |
| **Enter가 Jira로 새어 이슈가 생성됨** | 가장 큰 위험. 목록이 열렸을 때만 `preventDefault`+`stopPropagation`. 닫혀 있으면 손대지 않는다. 실사용 검증 필수 |
| `aria-label`이 언어 설정에 따라 바뀜 | 현재 UI가 한글인데 이 값은 영문이라 무관해 보이나 미확인. 조상 컨테이너 `data-testid`를 보조 앵커로 둔다 |
| IME 조합 중 오작동 | `isComposing`·`keyCode 229` 확인 |
| Jira가 나중에 `/`를 쓰기 시작함 | 그때는 우리 목록을 끄는 편이 맞다. 기능 토글로 끌 수 있게 한다 |
| `maxlength=255` 초과 | 템플릿 삽입 후 길이를 확인하고 넘치면 삽입하지 않는다 |

## 8. 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 업무 상세 제목 편집에 적용 | 다른 컴포넌트. 범위를 넓히지 않는다 |
| Confluence 편집기에 적용 | 그쪽은 Jira와 달리 자체 `/` 메뉴가 있다 |
| 템플릿 자동 분류·추천 | 단순 접두사 삽입이 요구사항이다 |
| 이슈 유형·담당자 등 다른 필드 자동 채움 | 요구 범위 밖 |

### Q4 정정 — 스프린트에는 인라인 생성이 없다

검토 단계에서 "백로그 + 스프린트"로 잡았으나 **틀렸다.** 선행 조사에서 스프린트 컨테이너
(`software-backlog.card-list.container.2177`)를 열어보니 생성 버튼도 입력창도 없었다.

| 컨테이너 | 인라인 생성 |
| --- | --- |
| `...container.BACKLOG` | **있음** |
| `...container.<스프린트id>` | **없음** |

인라인 생성은 백로그 영역 전용이다. 범위가 줄었다.

## 9-2. 설정 화면으로 가는 길 — service worker를 처음 두었다

태그를 하나 더 넣자고 Popup을 열어 메뉴를 세 번 타고 들어가는 것이 번거롭다는 요청으로
목록 맨 아래에 `＋ prefix 태그 추가·관리…` 버튼을 넣었다.

### 왜 service worker가 필요한가

content script에서 확장 페이지를 여는 길이 전부 막혀 있다.

| 시도 | 결과 |
| --- | --- |
| `chrome.windows.create` | content script에 **없는 API** |
| `chrome.runtime.openOptionsPage` | content script에 **노출되지 않는다** |
| `window.open(chrome.runtime.getURL(...))` | 웹 페이지 컨텍스트의 `chrome-extension://` 최상위 이동은 **브라우저가 막는다** |

그래서 메시지를 보내고 service worker가 창을 연다. 이 저장소에 service worker가 생긴 것은
이번이 처음이다. **하는 일은 이것 하나다.**

### `chrome.action.openPopup()`을 쓰지 않은 이유

Chrome 127부터 모든 확장이 쓸 수 있고 실제 브라우저도 152라 동작은 한다. 그런데 그쪽은
`default_popup`에 적힌 주소를 그대로 연다. **원하는 화면으로 바로 보낼 수 없다.** 버튼을
만든 이유가 "메뉴를 타고 들어가기 번거로워서"인데 그러면 아무것도 해결되지 않는다.

`chrome.windows.create({ type: 'popup' })`는 URL을 자유롭게 줄 수 있어 해시 라우트를 붙여
곧장 prefix 태그 표로 보낸다. Popup CSS가 `width: 520px`이라 창 크기는 `536 × 700`으로 뒀다.

### 키보드로 선택되지 않아야 한다

요청 그대로다. `Enter`로 닿으면 태그를 넣으려다 창이 뜬다 — 입력하던 제목을 두고 화면이
바뀌는 셈이다. 다른 항목이 **입력을 채우는** 동작인 데 비해 이것은 **화면을 여는** 동작이라
성격도 다르다.

목록 항목 배열(`matches`) 밖에 두고 `tabindex="-1"`을 준다. `↓` `↑`는 `matches` 길이 안에서만
돌고, `Enter`·`Tab`은 `matches[activeIndex]`를 넣으므로 이 버튼에 닿을 길이 없다.

## 10. 실사용 접두사 조사

기본 템플릿을 정하려고 실제 백로그 제목 37개에서 접두사를 모았다. **16종**이 쓰이고 있었다.

| 접두사 | 빈도 |
| --- | --- |
| `[INFRA]` | 9 |
| `[GitOps]` | 4 |
| `[개발환경]` | 3 |
| `[Identity]` · `[CI/CD]` | 각 2 |
| `[DevOpsit][BE]` · `[Database]` · `[Credential]` · `[Deploy]` · `[Common]` · `[공통]` · `[점검/배포]` · `[서비스메시]` · `[옵저버빌리티]` · `[백업관리]` · `[기타]` | 각 1 |
| 접두사 없음 | 6 |

기본값은 요청받은 3종으로 두었다. **코드에 박지 않고 Popup에서 편집하게 한 판단이 이 조사로
뒷받침된다** — 실사용 접두사가 기본값보다 훨씬 많고 계속 늘어난다.

`[CI/CD]`와 `[점검/배포]`처럼 **접두사 안에 `/`가 들어가는 경우**가 있다. 슬래시 토큰은 첫
글자 기준이고 공백에서 끊기므로 필터·삽입에 영향이 없다.
