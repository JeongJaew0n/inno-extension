# 보드 활성 스프린트 정보 — 설계

- 상태: **구현 완료 · 실사용 확인 대기**
- 작성일: 2026-09-18
- 실측: [context.md](./context.md)

## 1. 어디서 값을 가져오나

**페이지가 이미 들고 있는 `window.SPA_STATE` 를 읽는다. 네트워크 요청은 하지 않는다.**

```
window.SPA_STATE.UIF_BOARD['uif-board::rapidboard-board::<boardId>'].data.result.sprints[]
```

후보가 둘이었다.

| 안 | 장점 | 단점 | 판정 |
| --- | --- | --- | --- |
| `스프린트 세부 정보` 팝업을 열어 읽기 | 사람이 보는 값 그대로 | **우리가 UI를 조작한다.** 깜빡이고 사용자 조작과 충돌 | 버림 |
| **`SPA_STATE` 읽기** | 화면을 건드리지 않음 | Jira 내부 상태 모양에 기댄다 | **채택** |

`SPA_STATE` 는 MAIN world 객체라 content script 에서 보이지 않는다. Jira 에 이미 MAIN world
진입점이 있으므로 그 옆에 읽기 전용 브리지를 하나 더 둔다.

## 2. 무엇을 보여주나

```
📅 9/9 ~ 9/30 · 8일 남음 · <목표>
```

- 목표(`goal`)가 있으면 뒤에 붙인다. 없으면 기간만 나온다.
- 넘치면 말줄임하고 전체는 hover 로 본다(최대 320px).
- hover 문구는 `스프린트 이름` / `전체 날짜 (남은 일수)` / `목표: …` 세 줄이다.

> **목표가 없으면 hover 에 `목표: 설정되지 않음` 이라고 적는다.** 빈 줄로 두면 설정이 안 된
> 것인지 못 읽은 것인지 구분되지 않는다.

측정한 보드의 `goal` 은 **빈 문자열**이었다. 지금 화면에는 기간만 나온다.

## 3. 자리

`[data-testid="software-filters.ui.list-filter-container"]` 끝에 붙인다. 필터 목록의 마지막이
`빠른 필터` 이므로 그 오른쪽이 된다.

## 4. 실패하면 아무것도 보여주지 않는다

- `SPA_STATE` 경로가 사라지면 빈 배열이 오고 칩을 붙이지 않는다. **보드를 망가뜨리지 않는 쪽을
  택한다.** 원인을 못 찾는 일이 없게 페이지당 한 번 콘솔에 남긴다.
- 날짜를 파싱하지 못하면 역시 아무것도 보여주지 않는다. **절반만 맞는 기간을 띄우는 것보다 낫다.**
- 브리지가 1초 안에 답하지 않으면 포기한다.

## 5. 적용 범위

| 화면 | 포함 |
| --- | --- |
| 활성 스프린트 보드 (`/boards/<id>`) | **포함** |
| 백로그 (`/boards/<id>/backlog`) | 제외 |
| 그 외 | 제외 |

## 6. 알려진 취약점

- **Jira 내부 상태 모양에 기댄다.** 빌드가 바뀌면 경로가 사라질 수 있다. 그때는 조용히 빠진다.
- **SPA 이동 시 신선도를 확인하지 못했다.** 캐시 항목에 `expiresAt` 이 있어 갱신될 것으로 보이나
  실측하지 않았다. 스프린트를 완료·시작한 직후 값이 옛것일 수 있다.
- 활성 스프린트가 여럿인 보드에서는 **첫 번째 것만** 보여준다.
