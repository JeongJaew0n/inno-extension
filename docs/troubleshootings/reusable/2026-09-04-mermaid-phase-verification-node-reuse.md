# 대량 변환 직후 Mermaid 변환이 전부 실패했다

- 발생일: 2026-09-04
- 상태: **재현 실패. 유력 원인에 대한 대응만 적용**
- 신고 내용: 새로고침 후 `Markdown 변환`을 눌렀더니 Mermaid 7개가 변환되지 않았다

## 1. 무슨 일이 있었나

한 번의 클릭에서 1·2단계는 **완벽히 동작했다.**

| 항목 | 변환 전 | 변환 후 |
| --- | --- | --- |
| 문단 | 697 | **80** |
| heading | 0 | **36** |
| table | 0 | **28** |
| 코드블럭 | 0 | **18** |
| **Mermaid 컴포넌트** | 0 | **0** |

3단계만 아무것도 만들지 못했다.

**그런데 곧바로 다시 누르니 1초 만에 7개 전부 성공했다.**

```text
t=964ms   "문단 1 · Mermaid 7 변환"   ext 0 -> 7, expand 0 -> 7
```

즉 문서나 원문의 문제가 아니라 **첫 클릭에서만 나타난 일시적 실패**다.

## 2. 배제한 원인 (전부 실측)

| 가설 | 측정 | 결과 |
| --- | --- | --- |
| CodeMirror 마운트 지연 | 붙여넣기 후 폴링 | 노드 생성·`.cm-content` 마운트·원문 읽기가 **353~379ms에 동시** 완료. 지연 없음 |
| `data-local-id` 지연 부여 | 새 코드블럭 폴링 | **생성 즉시 존재**하고 브리지 선택자로 바로 찾힘 |
| 브리지 1000ms 타임아웃 | 7개 순차 `read-node` | **합계 2ms** (최대 2ms). 여유가 500배 |
| expand 중첩 | 코드블럭 위치 확인 | 7개 모두 최상위, `inExpand: false` |
| 30줄 렌더 잘림 | 렌더 줄 수 | 6~16줄. 한계에 닿지 않음 |
| 짝 없는 컴포넌트 가드 | extension 수 | 0개. 가드가 걸릴 수 없음 |

## 3. 남은 유력 가설

`replaceMermaidCodeBlock()`의 성공 판정이 원본 노드의 연결 상태에 기대고 있었다.

```ts
const didReplaceSource = (): boolean => (
  !codeBlock.isConnected                                   // <- 이것
  && isMermaidReplacementAtOriginalPosition(...)
);
```

**ProseMirror는 DOM 노드를 재사용한다.** 같은 날 문단 변환 단계에서 이것을 실측으로 확인했다.
교체가 제대로 끝났는데도 원래 엘리먼트의 `isConnected`가 계속 `true`였다.

| 실측 | 값 |
| --- | --- |
| 문단 12개를 표 1개로 교체 | 성공 (문단 697 → 685, table 0 → 1) |
| 그때 `!first.isConnected && !last.isConnected` | **`false`** |

앞 단계가 문서를 통째로 다시 쓴 직후라면 재사용 양상이 달라질 수 있다. 그러면 7개 모두 검증에
실패해 각각 3초 타임아웃 뒤 되돌려진다. **정황은 맞지만 재현하지 못했다.**

## 4. 적용한 대응

### 4.1 판정에서 노드 동일성을 걷어냈다

```ts
/**
 * 교체가 성공하면 원본은 둘 중 하나다. 노드가 버려졌거나, 재사용되어 `Mermaid 원본` 접힌
 * 영역 안으로 들어갔거나. 붙여넣기가 실패했다면 원본은 접히지 않은 채 제자리에 남는다.
 */
const didConsumeOriginal = (): boolean => (
  !codeBlock.isConnected || isCollapsedMermaidSource(codeBlock)
);
```

되돌리기 판정(`changed`)도 같은 기준으로 맞췄다. 문단 변환 단계는 이미 내용 기준으로 바꿔 둔
것을 Mermaid 단계에도 적용한 것이다.

### 4.2 실패 문구를 다음 클릭까지 남긴다

이 조사가 막힌 결정적 이유는 **원인 문구를 아무도 못 봤다는 것**이다. 결과 라벨이 2.2초 뒤
사라진다. 사용자도, 조사하는 쪽도 어느 분기에서 끊겼는지 확인할 수 없었다.

- 성공·무변경 → 종전대로 2.2초 뒤 원래 라벨로 복귀
- **실패·미변환 진단 → 다음 클릭까지 유지**

버튼은 곧바로 다시 누를 수 있게 풀어두고 라벨과 hover 문구만 남긴다. 다음 클릭이 `확인 중`으로
덮어쓴다.

## 5. 확인하지 못한 것

- **원인을 확정하지 못했다.** 3절은 가설이다. 대량 변환 직후 상태를 재현하려면 문서를 변환 전으로
  되돌려야 하는데, 사용자의 문서가 이미 정상 변환된 상태라 되돌리지 않았다.
- 실패 당시 버튼의 hover 문구를 확보하지 못했다. 4.2 대응으로 다음부터는 확인할 수 있다.

## 6. 다음에 같은 일이 생기면

버튼에 마우스를 올려 **hover 문구**를 확인한다. 이제 다음 클릭 전까지 남아 있다. 문구로 분기가
특정된다.

| 문구 | 끊긴 지점 |
| --- | --- |
| `원래 위치의 컴포넌트로 교체하지 못했습니다` | 3,000ms 검증 미통과 |
| `브리지가 응답하지 않았습니다` | ProseMirror 선택 1,000ms 무응답 |
| `원문을 읽지 못했습니다` | 브리지 `read-node` 실패 |
| `문서 다른 위치에 Mermaid 컴포넌트 N개가 있습니다` | 짝 없는 컴포넌트 가드 |
