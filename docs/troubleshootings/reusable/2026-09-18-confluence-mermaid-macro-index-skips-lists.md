# Confluence Mermaid 매크로는 목록 안의 코드블럭을 세지 않는다

- 발생일: 2026-09-17 · 원인 확정 2026-09-18
- 원인 위치: **Confluence Mermaid Forge 앱** (우리 코드가 아니다)
- 상태: **원인 확정 · 대응함**

## 증상

Mermaid 매크로가 엉뚱한 코드블럭을 다이어그램으로 읽으려다 실패한다.

```
Error while loading diagram
No diagram type detected matching given configuration for text:
2. https://0c3bb825-...:6443 → kube-system uid = A ...
```

문서에 코드블럭이 **목록 항목 안에 들어 있을 때**만 일어난다. 그런 블록이 없으면 정상 동작한다.

## 매크로의 원본 참조 방식

매크로는 다이어그램 원문을 자기 안에 담지 않는다. `guestParams.index` 로 **페이지의 N번째
코드블럭**을 읽는다. 그래서 순번이 어긋나면 남의 코드블럭을 그리려 한다.

## 확정 과정

실패한 페이지에서 **우리가 실제로 넣은 값**을 읽었다.

```js
extension.pmViewDesc.node.attrs.parameters.guestParams.index   // → 3
```

같은 시점 문서의 코드블럭 배치는 이랬다.

| 우리 순번 | 내용 | 자리 |
| --- | --- | --- |
| 0 | `spec:` | 최상위 |
| **1** | `{` | **목록 안** |
| 2 | `app:` | 최상위 |
| **3** | **`flowchart TD`** | expand 안 |
| 4 | `2. https://0c3bb825-...` | 최상위 |
| 5 | `[SE 에서 클러스터 등록 시 1회]` | 최상위 |
| **6** | **`sequenceDiagram`** | expand 안 |

**우리는 맞게 넣었다.** 3번은 실제로 flowchart다. 그런데 매크로는 다른 것을 읽었다.

### 두 가설을 예측으로 갈랐다

| 우리가 넣은 값 | 매크로가 전부 센다면 | **목록 안을 뺀다면** |
| --- | --- | --- |
| `3` | `flowchart TD` (정상) | **`2. https://0c3bb825-...`** |
| `6` | `sequenceDiagram` (정상) | **(범위 밖)** |

실제 결과는 **플로차트가 `2. https://0c3bb825-...` 를 읽어 실패**했고 **시퀀스 다이어그램도 함께
그려지지 않았다.** 두 예측이 모두 `목록 안을 뺀다` 쪽과 맞는다.

### expand 안은 센다

변환 결과의 원본은 **항상 `expand` 안**으로 들어간다. 매크로가 중첩을 전부 세지 않는다면 이
기능은 한 번도 동작하지 못했어야 하는데 잘 돼 왔다. 그러므로 규칙은 "중첩 제외"가 아니라
**"목록 안 제외"** 다.

## 관찰된 규칙

| 코드블럭 자리 | 매크로가 세나 |
| --- | --- |
| 최상위 | **센다** |
| `expand` 안 | **센다** |
| 목록 안 | **세지 않는다** |
| 그 외(표 칸·인용 등) | **확인하지 못했다** |

## 대응

`macro-index.ts` 에서 **매크로가 세는 방식대로** 순번을 따로 계산한다. 우리가 검증에 쓰는 DOM
순번과 매크로에 넣는 순번을 분리했다.

확인하지 못한 자리의 코드블럭이 **앞쪽에 하나라도 있으면 매크로를 만들지 않는다.** 순번을 맞출 수
없는데 만들면 깨진 다이어그램이 된다. 만들지 않고 이유를 알리는 편이 낫다.

실제 문서에 고친 계산을 적용한 결과다.

```
domIndex 3 (flowchart)       → macroIndex 2 → 매크로가 읽는 것: flowchart TD
domIndex 6 (sequenceDiagram) → macroIndex 5 → 매크로가 읽는 것: sequenceDiagram
```

## 교훈

**외부 앱이 순번으로 무언가를 참조하면, 그 앱이 세는 방식이 우리와 같다고 가정하지 않는다.**
여기서는 "코드블럭 목록"이라는 같은 말이 서로 다른 집합을 가리켰다.

가설이 둘로 갈릴 때는 **각 가설이 내놓는 서로 다른 예측**을 먼저 적고 실제와 대조하면 한 번에
갈린다. 이 건은 두 번째 매크로가 "범위 밖"이 된다는 예측이 결정적이었다.
