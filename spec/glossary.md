# 용어사전

- 상태: Active
- 최종 갱신일: 2026-08-07

제품 기획, 기능 spec, 사용자 UI에서 같은 개념을 일관되게 부르기 위한 기준 용어다. 코드의 기존 식별자는 저장 설정과 호환성 때문에 사용자 용어와 다를 수 있다.

## 제품 구조

### 제품

`Inno Extension` 전체를 뜻한다. 여러 서비스와 그 하위 기능을 하나의 Chrome 확장 프로그램으로 제공한다.

### 서비스

아마란스, Jira, Confluence처럼 기능을 묶는 최상위 업무 시스템 단위다.

- 공식 사용자 용어: `서비스`
- 예시: `아마란스 서비스`, `Jira 서비스`, `Confluence 서비스`
- UI 예시: `서비스 목록`, `서비스 카드`, `서비스 상세`, `서비스 전체 기능`
- 코드 대응어: `Site`

서비스는 화면에서 가장 큰 메뉴처럼 보일 수 있지만 UI 배치가 바뀌어도 유지되는 제품 도메인 개념이다. 따라서 `root`, `대메뉴`는 공식 용어로 사용하지 않는다.

현재는 서비스 하나와 대상 웹사이트 하나가 일대일로 대응하지만, 서비스는 제품 분류이고 사이트는 기술적 접속 대상을 뜻하므로 개념을 구분한다.

### 사이트

기능이 실제로 실행되는 웹 origin 또는 페이지 범위를 뜻하는 기술 용어다.

- 예시: `https://gw.innogrid.com`, `https://pms-innogrid.atlassian.net`
- 사용 위치: Manifest 권한, content script 적용 범위, URL·DOM 조건 설명
- 사용자 메뉴 분류를 가리킬 때는 `사이트` 대신 `서비스`를 사용한다.

### 기능

서비스 아래에서 독립적으로 켜고 끌 수 있는 사용자 편의 단위다.

- 예시: `헤더 출퇴근 버튼`, `업무 링크 복사`, `본문 Markdown 복사`
- 각 기능은 적용 조건, 사용자 행동 계약, 설정, 실패·복구 동작을 독립적으로 가진다.
- 코드 대응어: `Feature`

### 서비스 전체 기능

한 서비스에 속한 모든 기능의 실행 여부를 제어하는 상위 gate다.

- 코드와 기술 문서에서 `site gate`, `site enabled`, `site master`로 표현될 수 있다.
- OFF로 바꿔도 하위 기능별 선택값은 보존한다.
- 다시 ON으로 바꾸면 이전 기능 조합을 복원한다.
- 사용자 UI에서는 `서비스 전체 기능` 또는 문맥이 명확할 때 `전체 기능`으로 표현한다.

## Jira 관련 용어

### 업무

Jira의 `issue`에 대응하는 사용자 표시 용어다. 사용자 UI와 기획 문서에서는 `이슈`보다 `업무`를 우선한다.

내부 코드의 `issueKey`, `selectedIssue`, `issueLinkCopy` 같은 식별자는 Jira API·URL 및 기존 설정 호환성을 위해 유지할 수 있다.

### 업무 번호

`NPT-38`처럼 Jira 업무를 식별하는 키다. 코드와 Jira 기술 문맥에서는 `issue key`로 표현될 수 있다.

### 업무 링크

업무 번호로 만든 Jira 정규 URL이다.

```text
https://pms-innogrid.atlassian.net/browse/{업무번호}
```

## 기술·운영 용어

### 적용 조건

서비스와 기능이 ON인 것 외에 URL, 선택 상태, 필수 DOM 존재 여부 등 기능이 실제로 표시·실행되기 위해 만족해야 하는 조건이다.

### 정본

현재 제품 결정과 행동 계약을 판단할 때 우선하는 문서다. 현재 정본은 `spec/`이며, `docs/plans/`는 구현 당시의 계획과 이력 자료다.

## 변경 이력

- 2026-08-07: Confluence를 독립된 서비스 예시에 추가했다.
