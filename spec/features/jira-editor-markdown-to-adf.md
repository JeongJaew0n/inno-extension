# Jira 설명 Markdown 변환

- 상태: Active
- 최종 갱신일: 2026-09-17
- 내부 기능 ID: `editorMarkdownToAdf`
- 기본값: **OFF**

## 한 줄 요약

Jira 업무 **설명** 편집기에서 코드블럭이나 문단으로 남은 Markdown을 제목·표·목록으로 바꾼다.

## 배경과 사용자 문제

다른 곳에서 쓴 Markdown을 Jira 설명에 옮기면 문법이 그대로 글자로 남는다. `## 제목`이 제목이
되지 않고 `|`로 그린 표가 문자열로 보인다. 손으로 다시 만들면 표 하나에 몇 분이 걸린다.

같은 문제를 Confluence에서 먼저 풀었다. **Jira도 같은 Atlassian ADF 편집기를 쓴다.**

## 목표

- 붙여넣은 Markdown을 제자리에서 실제 블록으로 바꾼다.
- 실패하면 되돌린다. 내용을 잃지 않는다.

## 비목표

- **Mermaid 다이어그램을 만들지 않는다.** 아래 참조.
- **댓글 편집기는 대상이 아니다.** 설명만 다룬다.
- 업무 제목·다른 필드는 편집기가 아니라 대상이 아니다.

## Mermaid는 지원하지 않는다

Jira에 Mermaid 앱이 설치돼 있지 않다. 편집기 삽입 메뉴에서 직접 확인했다.

| 검색어 | 결과 |
| --- | --- |
| `mermaid` | 일치하는 검색 결과 없음 |
| `diagram` | 일치하는 검색 결과 없음 |
| `code` | `코드 조각` — 검색 자체는 정상 |

Confluence 기능이 넣는 Forge 확장은 Confluence 쪽 앱 설치에 묶여 있다. 같은 노드를 Jira에 넣어도
그릴 주체가 없다.

**Mermaid 코드블럭은 코드블럭으로 남는다.** 원문이 사라지지 않으므로 손해는 없고, 다이어그램이
되지 않을 뿐이다. 앱 설치는 사이트 관리자 권한이고, 이미지로 대체하려면 외부 요청이 필요한데
이 확장은 네트워크 요청을 하지 않는다.

## 적용 범위와 활성 조건

- Jira 서비스와 이 기능이 모두 ON일 때 동작한다. **기본값은 OFF다.**
- 대상은 업무 **설명** 편집기 하나다. 편집기가 열려 있을 때만 버튼이 나타난다.
- 앵커는 `[data-testid="issue.views.field.rich-text.editor-container"]`이고, 툴바와 본문을
  **그 안에서만** 찾는다.

> **Jira는 한 화면에 편집기가 여럿이다.** 설명과 댓글이 동시에 열릴 수 있고 각각
> `editor-primary-toolbar`를 만든다. 문서 전체에서 툴바를 찾으면 댓글 편집기에 버튼이 붙는다.
>
> `aria-label`("설명 영역입니다…")은 한국어라 언어 설정에 따라 바뀐다. 앵커로 쓰지 않는다.

## 사용자 경험

편집기 툴바 오른쪽에 `Markdown 변환` 버튼이 붙는다. 누르면 두 단계가 순서대로 돈다.

| 단계 | 하는 일 | 실행 조건 |
| --- | --- | --- |
| 1. 코드블럭 벗기기 | 원문을 담은 코드블럭을 해석해 원위치 ADF로 교체 | 아래 게이트를 통과할 때만 |
| 2. 문단 Markdown 변환 | 문단으로 남은 Markdown을 편집기 파서에 다시 맡긴다 | 대상 문단 구간이 있을 때 |

라벨이 진행 상황(`코드블럭 2/3`, `문단 Markdown 1/2`)과 결과(`코드블럭 1 · 문단 2 변환`)를 보여준다.

### 1단계는 함부로 돌지 않는다

벗기기는 코드블럭을 Markdown으로 해석해 **산문으로 풀어버린다.** 실제 소스 코드에 실행하면 코드가
사라진다. 세 조건을 모두 만족할 때만 돈다.

1. 코드블럭이 하나 이상 있다
2. 그중 최상위에 놓인 것이 하나 이상 있다
3. **전부** Markdown 문서로 보인다

하나라도 판정이 안 서면 벗기지 않는다.

### 2단계는 Jira 파서에 맡긴다

문단 구간의 텍스트를 이어 붙여 **평문으로 다시 붙여넣는다.** 그러면 Jira 자체 Markdown 파서가
제목·표·코드블럭·목록을 만든다. 실측으로 확인했다.

우리 변환기를 쓰지 않는 이유는 규칙이 다르기 때문이다. `marked`는 취소선 구분자로 물결표 1개도
인정해 `1~3장 ... 4~5장` 같은 범위 표기를 취소선으로 만들고 글자를 지운다.

## 동작 계약

### 저장은 우리가 누르지 않는다

변환은 **편집기 안의 내용만** 바꾼다. `저장`은 사용자가 누른다. 마음에 들지 않으면 `취소`로
통째로 버릴 수 있다.

### 편집기 상태 접근

ProseMirror `EditorView`는 페이지(MAIN world)에 있고 content script는 볼 수 없다. MAIN world에
브리지를 심어 `CustomEvent`로 주고받는다.

**대상 노드는 우리가 붙이는 임시 표식 속성으로 지정한다.** Jira에서 갓 불러온 문서의 노드에는
Atlassian의 `data-local-id`가 없기 때문이다. 요청이 끝나면 표식을 지운다.

Jira에서는 `pmViewDesc` 사슬로 `EditorView`를 찾지 못하고 **React fiber 탐색 폴백**이 찾는다
(실측 218노드 / depth 6 / 4ms).

### 실패와 되돌리기

각 교체는 붙여넣기 전 본문을 스냅샷으로 잡는다. 결과가 기대와 다르면 편집기의 실행 취소 버튼을
눌러 되돌린다. 되돌리기까지 실패하면 **사용자에게 직접 실행 취소를 누르라고 알린다.**

버튼 라벨에 짧은 원인(`변환 실패 · 편집기 응답 없음`)이 남고, hover 문구에 전체 메시지가 남는다.
실패·진단 결과는 **다음 클릭까지 사라지지 않는다.**

## 설정과 기본값

| 항목 | 값 |
| --- | --- |
| 기능 기본값 | **OFF** |
| 추가 옵션 | 없음 |

## 실패와 복구

- 컨테이너 `data-testid`가 바뀌면 버튼이 뜨지 않는다. **Jira 기본 동작은 그대로다.**
- 브리지가 응답하지 않으면 그 단계에서 멈추고 되돌린다.
- 변환할 것이 없으면 문단에 남은 Markdown 문법을 찾아 알려준다.

## 수용 기준

- 설명 편집기를 열면 툴바에 버튼이 나타나고, 닫으면 사라진다.
- **댓글 편집기에는 버튼이 붙지 않는다.**
- 코드블럭 하나에 담긴 Markdown 원문이 제목·표·목록으로 바뀐다.
- 문단으로 남은 Markdown이 제자리에서 바뀐다.
- Mermaid 코드블럭은 코드블럭으로 남는다.
- 실제 소스 코드가 든 코드블럭은 벗겨지지 않는다.
- 기능이 OFF면 아무것도 주입되지 않는다.

## 알려진 리스크와 열린 질문

- 전체 화면 업무 보기(`/browse/...`)가 모달과 같은 구조인지 **확인하지 않았다.**
- 30줄이 넘는 코드블럭의 DOM 잘림이 Jira에서도 같은지 확인하지 않았다. Confluence와 같은 대응
  (브리지로 원문을 읽는다)을 쓰고 있다.
- Jira 편집기 DOM이 바뀌면 깨진다. 남의 화면에 기대는 기능의 공통 한계다.

## 변경 이력

- 2026-09-17: 기능을 추가했다. Confluence 편집기 기능의 두 단계를 공용화해 Jira 설명 편집기에
  붙였다. Mermaid 단계는 Jira에 앱이 없어 제외했다. 기본값 OFF.
