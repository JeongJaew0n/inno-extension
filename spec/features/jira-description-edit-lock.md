# Jira 클릭 편집 방지

- 상태: Active
- 최종 갱신일: 2026-09-28
- 내부 기능 ID: `descriptionEditLock`
- 기본값: 기능 ON · 막기(`locked`) OFF

## 한 줄 요약

업무 설명을 클릭해도 편집으로 들어가지 않게 막고, 대신 `편집` 버튼으로만 들어가게 한다.

## 배경

Jira 설명은 본문 아무 데나 클릭하면 곧바로 편집 상태가 된다. 읽다가 글을 고르거나 링크 옆을
누르면 편집으로 넘어간다.

## 화면

`설명` 라벨 줄, `Markdown 복사` 왼쪽.

```
설명   클릭 편집 방지 [●]  [편집]  [Markdown 복사]
```

| 상태 | 스위치 | `편집` 버튼 | 본문 클릭 |
| --- | --- | --- | --- |
| 막기 OFF (기본) | 보임 | 없음 | Jira 기본 — 편집으로 들어간다 |
| 막기 ON · 읽는 중 | 보임 | **보임** | 편집으로 들어가지 않는다 |
| 막기 ON · 편집 중 | 보임 | 없음 | — |

## 설정

| 항목 | 값 |
| --- | --- |
| 저장 위치 | `chrome.storage.sync` |
| `locked` | 불리언. `true` 일 때만 막는다. 형식이 깨지면 `false` |

**막힘 상태는 기능 ON/OFF 와 별개다.** 합치면 끄는 순간 스위치가 사라져 Jira 화면에서 다시 켤 수
없다. 기능을 끄면 스위치와 막기가 모두 사라지고 Jira 기본 동작이 된다.

**전역 공유.** Jira 화면 스위치와 Popup 상세 설정 스위치가 같은 값이다. `storage.onChanged` 로
다른 탭과 Popup 이 함께 바뀐다.

## 동작 계약

- `window` capture 단계에서 `click` 을 `stopImmediatePropagation` 한다. React 루트에 닿기 전이라
  Jira 의 편집 전환이 일어나지 않는다.
- **설명 필드 안의 클릭만** 대상이다. 댓글과 다른 필드는 건드리지 않는다.
- **본문 렌더러 안의 링크·버튼·체크박스·펼치기는 통과시킨다.** 판단을 렌더러 안으로 한정하는
  이유는 설명 전체를 감싸는 Jira 의 클릭 영역이 `role="button"` 일 수 있어서다.
- `preventDefault` 는 하지 않는다. 링크 이동과 텍스트 선택은 그대로다.
- `편집` 버튼은 통과 플래그를 세우고 본문에 `click()` 을 보낸다. Jira 가 받던 것과 같은 클릭이다.
  설명이 비어 렌더러가 없으면 필드 자체를 누른다.
- 네트워크를 쓰지 않는다.

## 비목표

- 키보드(`Enter`)로 편집에 들어가는 경로는 막지 않는다.

## 알려진 리스크

- [미정] Jira 가 편집 전환을 `click` 이 아니라 `mousedown`/`mouseup` 으로 하면 막히지 않는다.
  만들 때 브라우저 실측을 하지 못했다. 막히지 않으면 이것부터 확인한다.

## 변경 이력

- 2026-09-28: 추가.
- 2026-09-28: 이름을 `편집 막기`에서 `클릭 편집 방지`로 바꿨다. 편집 자체가 아니라 **클릭으로 들어가는 편집**만 막는다는 게 드러나는 이름이다. 기능 ID `descriptionEditLock`은 저장소 키라 그대로 둔다 — 바꾸면 이미 켜둔 설정이 사라진다.
