# Jira 설명 편집 취소 버튼

- 상태: Active
- 최종 갱신일: 2026-09-17
- 내부 기능 ID: `descriptionEditCancel`
- 기본값: ON

## 한 줄 요약

설명을 편집 중일 때 `설명` 제목 옆에 `취소` 버튼을 둔다.

## 배경과 사용자 문제

Jira 설명은 **본문을 클릭하면 곧바로 편집 상태**가 된다. 잘못 눌렀을 때 되돌리려면 문서 끝까지
스크롤해서 아래쪽 `취소`를 눌러야 한다. 설명이 길수록 멀다.

## 목표

- 편집을 시작한 자리에서 바로 취소한다.

## 비목표

- `저장`은 위에 두지 않는다. 되돌릴 수 없는 동작이라 더 신중해야 한다.
- 댓글 편집기는 대상이 아니다.

## 적용 범위와 활성 조건

- Jira 서비스와 이 기능이 모두 ON일 때 동작한다. **기본값은 ON이다.**
- **설명을 편집 중일 때만** 나타난다. 읽기 상태에서는 붙지 않는다.
- 판정은 `[data-testid="issue.views.field.rich-text.editor-container"]` 안에 취소 버튼이 있는지로 한다.

## 동작 계약

### 새 동작을 만들지 않는다

**아래쪽 `취소` 버튼을 그대로 누른다.** 편집 상태를 우리가 해제하지 않는다.

변경 사항이 있을 때 확인 대화상자를 띄울지, 초안을 남길지는 전부 Jira의 판단이고 그대로 유지된다.
흉내 내면 언젠가 갈린다.

### 댓글을 취소시키지 않는다

취소 버튼의 `data-testid`가 **`comment-cancel-button`** 이다. Jira가 설명 편집에도 댓글 편집기
컴포넌트를 재사용해서 붙은 이름이고, **진짜 댓글 입력창에도 같은 testid가 있다.**

문서 전체에서 찾으면 사용자가 쓰던 댓글이 날아간다. **설명 편집 컨테이너 안에서만 찾는다.**

### 다시 찾는다

클릭 시점에 버튼을 다시 찾는다. 그 사이 편집이 끝났을 수 있다. 못 찾으면 아무것도 하지 않고
콘솔에 남긴다.

## 설정과 기본값

| 항목 | 값 |
| --- | --- |
| 기능 기본값 | **ON** |
| 추가 옵션 | 없음 |

## 실패와 복구

- 아래쪽 버튼을 찾지 못하면 아무 일도 하지 않는다. **Jira 기본 동작은 그대로다.**
- 라벨 줄 구조가 바뀌면 버튼이 라벨 아래 줄에 놓인다. 동작은 유지된다.

## 수용 기준

- 편집을 시작하면 `설명` 옆에 `취소`가 나타나고, 끝나면 사라진다.
- 누르면 아래쪽 `취소`와 똑같이 동작한다.
- **댓글을 쓰는 중에는 나타나지 않는다.**
- 기능이 OFF면 아무것도 주입되지 않는다.

## 알려진 리스크와 열린 질문

- 변경 사항이 있을 때 Jira가 확인 대화상자를 띄우는지 **확인하지 못했다.** 아래쪽 버튼을 그대로
  누르므로 어느 쪽이든 Jira와 같게 동작한다.
- 전체 화면 업무 보기(`/browse/...`)의 구조를 확인하지 않았다.

## 변경 이력

- 2026-09-17: 기능을 추가했다. 기본값 ON.
