# Jira 백로그 prefix 태그

- 상태: Active
- 최종 갱신일: 2026-09-16
- 내부 기능 ID: `backlogSlashTemplate`
- 기본값: ON

## 한 줄 요약

백로그에서 업무를 추가할 때 `/`를 입력하면 등록된 **prefix 태그** 목록이 뜨고, 골라서 넣는다.

## 배경과 사용자 문제

팀은 업무 제목에 `[INFRA]`, `[CI/CD]` 같은 **prefix 태그**를 붙여 영역을 구분한다. 매번 손으로
치면 오타가 나고 표기가 흔들린다. 실제 백로그의 제목 37개에서 16종이 쓰이고 있었다.

Jira는 이 입력창에 자동완성을 제공하지 않는다. `/`에도 아무 동작이 걸려 있지 않아 비어 있다.

## 목표

- prefix 태그를 외우지 않고 고른다.
- 표기를 일정하게 유지한다.
- 팀·프로젝트마다 다른 태그를 사용자가 직접 관리한다.

## 비목표

- 업무 상세 화면의 제목 편집은 대상이 아니다. 다른 컴포넌트다.
- 이슈 유형·담당자 등 다른 필드를 채우지 않는다.
- 태그를 자동으로 추천하거나 분류하지 않는다.

## 적용 범위와 활성 조건

- Jira 서비스와 이 기능이 모두 ON일 때 동작한다. **기본값은 ON이다.**
- 대상은 **백로그 인라인 생성의 제목 입력창** 하나다.
- 입력창은 `input[aria-label="Work item summary"]`로 찾고, 카드 리스트 컨테이너 안에 있는
  것만 대상으로 한다.

> **스프린트 영역에는 인라인 생성이 없다.** 스프린트 컨테이너에는 생성 버튼도 입력창도 없는
> 것을 실측으로 확인했다. 인라인 생성은 백로그 영역 전용이다.

## 사용자 경험

### 트리거

**입력 첫 글자가 `/`일 때만** 목록을 연다.

| 입력 | 목록 |
| --- | --- |
| `/` | 켜둔 태그 전체 |
| `/git` | `[GitOps]` |
| `/GIT` | 위와 동일 (대소문자 무시) |
| `/cicd` | `[CI/CD]` (슬래시도 무시) |
| `버그 수정 src/sites` | 뜨지 않음 |
| `/git 작업` | 뜨지 않음 (공백 뒤는 본문) |

문장 중간의 `/`는 경로나 날짜에 흔하다(`src/sites/jira`, `9/16`). 중간 트리거를 허용하면 정상
입력을 방해한다.

### 필터

토큰이 항목에 **포함**되면 보여준다. 대소문자·대괄호·슬래시를 무시한다. 슬래시까지 무시하는
이유는 `[CI/CD]`처럼 태그 안에 `/`가 들어가는 경우가 실제로 있어서다. 결과가 없으면 닫는다.

### 선택과 삽입

| 키 | 동작 |
| --- | --- |
| `↓` `↑` | 항목 이동. 끝에서 반대편으로 돈다 |
| `Enter` `Tab` | 선택 항목 삽입 |
| `Esc` | 목록만 닫는다. 입력값은 그대로 |
| 마우스 | hover로 이동, 클릭으로 삽입 |

삽입하면 슬래시 토큰을 태그로 **치환**하고 뒤에 공백 하나를 붙인다. 커서는 그 뒤에 둔다.

```text
/git  →  [GitOps] ▌
```

결과가 입력창 최대 길이(255자)를 넘으면 삽입하지 않는다. 잘린 제목을 만드는 것보다 낫다.

## 동작 계약

### Enter 를 가로채는 조건

이 입력창의 `Enter`는 **이슈 생성**이다. 잘못 가로채면 정상적인 생성이 막힌다.

- **목록이 열려 있을 때만** 개입한다. 닫혀 있으면 아무것도 하지 않는다.
- `capture` 단계에서 듣고 `preventDefault` + `stopPropagation`으로 Jira의 `onKeyDown`에
  닿지 않게 한다.

### IME

한글·한자 조합 중에는 키 이벤트가 정상적이지 않고, 그때의 `Enter`는 후보 확정이다.
`event.isComposing`과 `keyCode === 229`를 확인해 조합 중에는 개입하지 않는다.

### 값 주입

입력창은 React controlled input이다. DOM 값만 바꾸면 다음 렌더에서 되돌아간다.
**native value setter로 넣고 `input` 이벤트를 쏜다.** 그래야 React 상태까지 갱신된다.

## 설정과 기본값

### prefix 태그

업무 제목 앞에 붙여 영역을 구분하는 대괄호 표기다. 두 종류로 나뉜다.

| 종류 | 출처 | 숨기기 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| **내장** | 확장이 제공 | 가능 | 불가 | **불가** |
| **커스텀** | 사용자 추가 | 가능 | 가능 | 가능 |

내장 태그는 여섯 개다.

```
[INFRA]  [IAM]  [CI/CD]  [GitOps]  [개발환경]  [점검/배포]
```

**내장 태그는 설정에 저장하지 않는다.** 코드에 두고 설정에는 **숨김 여부만** 남긴다. 통째로
저장하면 다음 릴리즈에서 내장 목록을 늘려도 이미 저장한 사용자는 옛 목록에 머문다.

| 항목 | 값 |
| --- | --- |
| 기능 기본값 | **ON** |
| 저장 위치 | `chrome.storage.sync` |
| `hiddenBuiltInTags` | 숨긴 내장 태그 라벨 |
| `customTags` | `{ label, visible }` 목록 |
| 태그 기본 표시 | **전부 ON** |

### Popup 편집

기능 상세에서 전체 목록을 보여준다.

- 각 항목의 체크박스로 **표시 여부**를 바꾼다. 끄면 `/` 목록에서 빠진다.
- 내장 태그에는 `기본` 배지를 달고 삭제 버튼을 두지 않는다.
- 커스텀 태그에는 `수정`·`삭제` 버튼을 둔다.
- 아래 입력란으로 새 태그를 추가한다.

중복은 만들지 않는다. 내장과 같은 라벨은 커스텀으로 추가되지 않고, 커스텀 이름을 내장 라벨로
바꿀 수도 없다.

보여줄 태그가 하나도 없으면 목록을 띄우지 않는다.

## 실패와 복구

- `aria-label`이 바뀌면 입력창을 찾지 못해 목록이 뜨지 않는다. **Jira 기본 동작은 그대로다.**
- 입력창이 사라지면 목록도 닫는다.
- 목록이 닫힌 상태에서는 어떤 키도 가로채지 않는다.

## 수용 기준

- `/`로 켜둔 태그 전체, `/git`으로 걸러진 목록이 뜬다.
- 선택하면 입력값이 태그로 치환되고 React 상태가 갱신된다.
- 내장 태그는 삭제 버튼이 없고, 숨긴 뒤 다시 켤 수 있다.
- **목록이 닫힌 상태의 `Enter`가 정상적으로 이슈를 만든다.**
- 목록이 열린 상태의 `Enter`는 이슈를 만들지 않는다.
- 한글 조합 중 오작동하지 않는다.
- 기능이 OFF면 아무것도 주입되지 않는다.

## 알려진 리스크와 열린 질문

- `aria-label="Work item summary"`가 사용자 언어 설정에 따라 바뀌는지 확인하지 못했다. 현재
  UI는 한글인데 이 값은 영문이다.
- 보드 화면에도 같은 입력창이 있는지 확인하지 않았다.
- Jira가 나중에 `/`에 자체 동작을 붙이면 충돌한다. 그때는 기능을 끄는 편이 맞다.

## 변경 이력

- 2026-09-16: 기능을 추가했다. 백로그 인라인 생성 입력창에서 `/`로 **prefix 태그**를 골라 넣는다.
  내장 태그 여섯 개를 제공하며 숨길 수는 있어도 삭제할 수 없다. 사용자는 커스텀 태그를 추가·수정·
  삭제할 수 있다. 기본값은 ON이고 모든 태그가 켜진 상태다.
