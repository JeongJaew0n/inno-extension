# 아마란스 신청서 제목 자동채움

- 상태: Active
- 최종 갱신일: 2026-08-04
- 대상 버전: 0.2.x

## 한 줄 요약

아마란스 근태신청서에서 반복적으로 입력하는 제목을 사용자가 미리 저장한 문구로 한 번에 채운다.

## 배경과 사용자 문제

근태신청서를 작성할 때 제목은 신청 건마다 직접 입력해야 한다. 같은 제목이나 조직 내에서 정한 표현을 반복해서 사용하는 경우에도 매번 타이핑해야 하며, 오탈자나 표현 불일치가 생길 수 있다.

이 기능은 제목 입력을 자동 수행하되, 신청서 제출이나 결재 상신은 사용자가 직접 검토하고 실행하도록 남겨 둔다.

## 목표

- 자주 사용하는 신청서 제목을 한 번의 클릭으로 입력한다.
- 자동채움 문구를 확장 프로그램 Popup에서 사용자가 직접 변경할 수 있게 한다.
- 기능 OFF, 서비스 OFF, 대상 화면 이탈 시 확장이 만든 UI를 남기지 않는다.
- 원본 입력 필드가 요구하는 변경 이벤트를 전달해 이후 검증과 제출 흐름이 정상적으로 동작하게 한다.

## 비목표

- 신청서 종류, 날짜, 신청자 정보에 따라 제목을 자동 생성하지 않는다.
- 신청서 본문, 근태 구분, 결재선, 첨부파일을 변경하지 않는다.
- 자동채움 직후 결재 상신이나 신청 완료를 실행하지 않는다.
- 여러 제목 프리셋이나 사용자별 공유 템플릿을 현재 범위에 포함하지 않는다.

## 대상 사용자와 적용 범위

- 서비스: 아마란스
- 사이트: `https://gw.innogrid.com`
- 화면: 근태신청서 작성 화면
- 대상 필드: 상신정보 영역의 `제목`

같은 서비스의 다른 화면이나 제목 이외의 입력 필드에는 버튼을 표시하지 않는다. 근태신청서 안에서 양식을 변경해 원본 DOM이 다시 그려지더라도 제목 필드가 존재하면 기능을 복구한다.

## 사용자 경험과 행동 계약

1. 사용자는 Popup에서 아마란스 서비스의 `신청서 제목 자동채움` 상세 화면을 연다.
2. `자동채움 내용`에 사용할 제목 문구를 입력하고 저장한다. 저장 버튼은 처리 중 상태와 완료 상태를 순서대로 표시한다.
3. 근태신청서 작성 화면의 `제목` 왼쪽에 `자동채움` 버튼이 표시된다.
4. 사용자가 버튼을 누르면 제목 입력란의 현재 값이 저장된 문구로 교체된다.
5. 입력 이후 커서는 제목 입력란에 위치하며, 사용자는 문구를 추가로 수정할 수 있다.

자동채움 문구가 비어 있으면 버튼은 화면에 표시하되 비활성화한다. 버튼에 마우스를 올리거나 키보드 포커스를 이동하면 `확장 프로그램 → 아마란스 → 신청서 제목 자동채움`에서 내용을 설정하라는 안내를 표시한다.

## 설정과 데이터

- 기능 기본값: ON
- 자동채움 문구 기본값: 빈 문자열
- 최대 길이: 원본 제목 필드와 같은 190자
- 저장 위치: 확장 프로그램의 동기화 설정
- 적용 방식: 저장된 단일 문구로 현재 제목 전체를 교체

문구의 앞뒤 공백은 제거한다. 최대 길이를 넘는 값은 원본 필드 제한에 맞춰 190자까지만 사용한다. 기능이나 아마란스 서비스 전체를 꺼도 저장된 문구는 보존한다.

## 기술적 맥락과 제약

- 아마란스는 SPA이며 신청서 종류 변경이나 화면 갱신 때 제목 영역이 다시 생성될 수 있다.
- 제목 입력란은 화면 프레임워크가 상태를 관리하므로 단순한 DOM 속성 변경만으로는 원본 애플리케이션이 변경을 인식하지 못할 수 있다.
- 기능은 원본 입력값을 변경한 뒤 일반적인 입력·변경 신호를 전달해야 한다.
- 제목 필드 식별은 외부 서비스의 DOM 구조에 의존하므로 화면 개편 시 재검증이 필요하다.
- 기능을 위해 새로운 Chrome 권한이나 사내 API 접근을 추가하지 않는다.

## 보안과 개인정보

- 자동채움 문구는 사용자의 확장 프로그램 설정에만 저장한다.
- 문구를 별도 서버로 전송하지 않는다.
- 현재 신청서의 다른 내용, 결재 정보, 첨부파일을 읽거나 저장하지 않는다.
- 사용자의 명시적 버튼 클릭 없이 제목을 변경하지 않는다.

## 주요 결정과 트레이드오프

### 독립 기능으로 제공

기존 헤더 출퇴근 버튼과 적용 화면·설정·사용 목적이 다르므로 별도 기능으로 제공한다. 사용자는 두 기능을 독립적으로 켜고 끌 수 있다.

### 자동 생성보다 사용자 설정 문구 우선

신청서 종류나 날짜에서 제목을 추론하면 편리할 수 있지만 조직의 제목 규칙을 잘못 가정할 위험이 있다. 현재는 사용자가 확정한 단일 문구만 사용한다.

### 덧붙이기보다 전체 교체

버튼을 여러 번 눌러도 제목이 중복되지 않도록 현재 입력값 전체를 저장 문구로 교체한다. 자동채움 후의 세부 수정은 사용자가 직접 한다.

### 빈 설정은 비활성 버튼으로 표현

임의의 기본 문구를 넣지 않는다. 설정되지 않은 상태를 숨기지 않고 비활성 버튼과 안내로 표시해 기능의 위치와 설정 필요성을 함께 알린다.

## 실패와 복구 동작

- 대상 화면이 아니거나 제목 필드를 찾지 못하면 버튼을 표시하지 않는다.
- 화면 재렌더로 버튼이 제거되면 제목 필드가 다시 확인되는 시점에 한 번만 복구한다.
- 기능 또는 서비스가 꺼지면 버튼과 전용 스타일을 제거한다.
- 자동채움에 실패해도 원본 제목 입력과 결재 상신 기능은 그대로 사용할 수 있어야 한다.

## 수용 기준

- 근태신청서 작성 화면에서 `제목` 왼쪽에 `자동채움` 버튼이 보인다.
- Popup에서 문구를 저장한 뒤 버튼을 누르면 제목 입력란이 해당 문구로 교체된다.
- Popup 저장 버튼이 `저장 중…`, `저장됨` 상태를 보여 저장 완료 여부를 알 수 있다.
- 입력된 제목을 사용자가 이어서 수정할 수 있다.
- 빈 문구에서는 버튼이 비활성화된다.
- 비활성 자동채움 버튼을 호버하거나 키보드로 포커스하면 설정 경로가 안내된다.
- 기능 토글 또는 아마란스 서비스 토글을 끄면 버튼이 제거된다.
- 화면 갱신이나 신청서 양식 변경 뒤에도 버튼이 중복 없이 복구된다.
- 다른 아마란스 화면에는 버튼이 표시되지 않는다.
- typecheck, unit test, production build가 성공한다.

## 알려진 리스크와 열린 질문

- 아마란스가 제목 필드의 식별자나 상신정보 표 구조를 변경하면 기능이 표시되지 않을 수 있다.
- 향후 신청서 종류별 문구, 날짜 치환, 여러 프리셋이 필요해질 수 있으나 현재 요구사항에는 포함하지 않는다.
- 동기화 설정을 사용하는 브라우저 환경에 따라 문구가 같은 Chrome 계정의 다른 기기로 동기화될 수 있다.

## 변경 이력

- 2026-08-04: 근태신청서 제목 왼쪽에 사용자 설정 문구를 입력하는 자동채움 버튼을 추가했다. 반복 입력을 줄이되 결재 상신은 사용자에게 남기기 위해 명시적 클릭 방식으로 결정했다.
- 2026-08-04: Popup 저장 버튼에 처리·성공·실패 피드백을 추가하고, 빈 문구로 비활성화된 자동채움 버튼에 설정 경로 안내를 추가했다.
