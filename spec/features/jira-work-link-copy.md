# Jira 업무 링크 복사

- 상태: Active
- 최종 갱신일: 2026-08-11
- 내부 기능 ID: `issueLinkCopy`
- 기본값: ON

## 한 줄 요약

Jira 보드에서 선택한 업무 번호 옆에 복사 버튼을 제공해, 업무 링크만 또는 업무 링크와 현재 제목을 함께 클립보드로 복사한다.

## 배경과 사용자 문제

메신저, 문서, 이메일, 코드 리뷰에서 Jira 업무를 공유할 때 사용자는 업무 번호와 제목을 다시 입력하거나 주소창·업무 제목을 각각 복사해야 한다. Jira 자체의 링크 복사 기능은 화면 위치나 붙여넣기 결과가 사용자가 원하는 형식과 다를 수 있다.

이 기능은 현재 보고 있는 업무의 정규 링크를 업무 번호에 연결해 복사하고, 필요하면 현재 제목까지 한 번에 포함한다. 공유 대상에 따라 짧은 링크와 설명이 있는 링크를 즉시 선택할 수 있게 하는 것이 핵심 가치다.

## 목표

- 모든 Jira 보드에서 선택한 업무와 직접 연 Jira 업무 조회 화면의 링크를 동일한 방식으로 복사한다.
- 짧은 공유용과 제목 포함 공유용을 별도 버튼으로 명확하게 제공한다.
- rich text를 지원하는 붙여넣기 대상에서는 업무 번호의 링크를 유지한다.
- plain text 환경에서도 읽을 수 있는 안정적인 대체 형식을 제공한다.
- Jira API나 추가 인증 없이 현재 화면과 사용자 클릭만으로 동작한다.

## 비목표

- Jira 업무 설명, 담당자, 상태, 우선순위 등 추가 메타데이터를 복사하지 않는다.
- Markdown 문법을 고정 출력하지 않는다.
- 업무 링크를 외부 서버에 저장하거나 전송하지 않는다.
- Jira의 기본 링크 복사 기능을 제거하거나 대체하지 않는다.
- 보드에 보이는 모든 업무를 일괄 복사하지 않는다.
- 사용자가 클릭하지 않은 상태에서 자동으로 클립보드를 변경하지 않는다.

## 용어

- 사용자 표시 용어는 `이슈`가 아니라 `업무`를 사용한다.
- 내부 식별자와 기존 저장 설정의 호환성을 위해 기능 ID `issueLinkCopy`는 유지한다.
- `업무 링크`는 `https://pms-innogrid.atlassian.net/browse/<업무번호>` 형식의 정규 URL을 뜻한다.

## 적용 범위와 활성 조건

기능은 다음 조건을 모두 만족할 때 활성화된다.

- Jira 서비스 전체 기능이 ON이다.
- `업무 링크 복사` 기능이 ON이다.
- 대상 origin이 `https://pms-innogrid.atlassian.net`이다.
- Jira software board의 기본 화면이며 URL에 선택 업무가 존재하거나, URL이 `/browse/{업무번호}` 또는 `/issues/{업무번호}` 직접 업무 조회 주소다.
- 선택 업무 상세 dialog에서 현재 업무 번호 링크를 찾을 수 있다.

지원 URL의 개념적 형식은 다음과 같다.

```text
/jira/software/c/projects/{projectKey}/boards/{boardId}?selectedIssue={issueKey}
```

프로젝트 키와 보드 ID는 제한하지 않는다. 초기 버전의 `NPT / 2146` 제한은 제거되었다.

현재 backlog, timeline, calendar, reports 같은 보드 하위 view path는 업무 링크 복사 적용 범위에 포함하지 않는다. 직접 업무 조회 화면은 보드 하위 view와 별개로 지원한다.

## 사용자 경험

선택 업무 dialog의 현재 업무 번호 옆에 다음 두 버튼을 표시한다.

| 버튼 | 목적 | plain text 결과 |
| --- | --- | --- |
| `업무 링크 복사` | 가장 짧은 업무 참조 복사 | `NPT-38` |
| `업무 링크 복사(제목포함)` | 문맥을 포함한 업무 참조 복사 | `NPT-38 현재 업무 제목` |

공통 동작은 다음과 같다.

- 버튼을 누르면 처리 중임을 표시한다.
- 복사가 성공하면 잠시 `복사됨`을 표시한다.
- 실패하면 잠시 `복사 실패`를 표시한다.
- 피드백 이후 원래 버튼 문구와 활성 상태로 돌아온다.
- 두 버튼은 서로 독립적으로 동작한다.

업무가 바뀌면 기존 버튼은 정리되고 새로 선택한 업무를 기준으로 갱신되어야 한다. 기능 또는 Jira 사이트가 OFF가 되거나 지원 범위를 벗어나면 주입된 버튼은 제거되어야 한다.

## 클립보드 계약

### 업무 링크 복사

```text
text/plain: NPT-38
text/html:  <a href="https://pms-innogrid.atlassian.net/browse/NPT-38">NPT-38</a>
```

### 업무 링크 복사(제목포함)

```text
text/plain: NPT-38 현재 업무 제목
text/html:  <a href="https://pms-innogrid.atlassian.net/browse/NPT-38">NPT-38</a> 현재 업무 제목
```

제목 앞에는 공백 하나를 둔다. 제목의 앞뒤 공백과 중복 공백은 정리한다. HTML payload에서 제목은 링크 바깥의 일반 텍스트이며, HTML 특수문자는 escape해 제목이 markup으로 해석되지 않게 한다.

붙여넣기 대상이 rich text를 지원하면 업무 번호에 링크가 유지된다. plain text만 지원하면 위 `text/plain` 값으로 대체된다.

## 제목의 기준

제목 포함 버튼은 클릭 시점에 열린 업무 상세 dialog의 현재 제목을 사용한다. 버튼이 처음 표시된 뒤 사용자가 제목을 편집한 경우에도 가능한 한 최신 화면 값을 복사하기 위한 결정이다.

제목을 읽을 수 없으면 제목 없는 결과로 조용히 대체하지 않는다. 사용자가 제목 포함 버튼을 선택했으므로 복사 실패로 처리해 잘못된 결과를 성공처럼 제공하지 않는다.

## 설정과 기본값

- Jira 서비스 기본값: ON
- 업무 링크 복사 기본값: ON
- 별도 세부 옵션: 없음

서비스 전체 OFF는 기능별 enabled 값을 변경하지 않는다. 서비스를 다시 ON으로 바꾸면 이전의 업무 링크 복사 설정을 복원한다.

## 기술적 맥락과 제약

- Jira는 SPA이므로 선택 업무와 직접 업무 화면 이동이 전체 페이지 reload 없이 일어날 수 있다.
- 보드에서는 URL의 `selectedIssue`와 dialog DOM을 함께 사용하고, 직접 업무 화면에서는 URL의 업무 번호와 본문 제목 영역을 사용한다.
- 업무 번호와 제목은 현재 URL과 DOM에서 읽는다. 별도의 Jira REST API 요청은 하지 않는다.
- Jira가 제공하는 안정적인 `data-testid`를 우선 사용하지만 이는 외부 UI 계약이 아니므로 변경 가능성이 있다.
- 클립보드 쓰기는 사용자 클릭 이벤트 안에서 수행한다.
- rich clipboard가 거부되면 plain text Clipboard API를 시도하고, 그것도 사용할 수 없으면 DOM 기반 복사를 마지막으로 시도한다.
- 추가 `clipboardWrite` 권한 없이 동작하는 것을 기본 원칙으로 한다.

이 문서는 특정 함수 구조나 selector 상수 이름을 고정하지 않는다. 현재 DOM 의존성과 fallback 순서는 기능의 행동·보안·호환성에 영향을 주므로 제품 제약으로 기록한다.

## 보안과 개인정보

- 클립보드에는 사용자가 명시적으로 선택한 업무 번호, 정규 URL, 선택적으로 현재 제목만 기록한다.
- 업무 본문, 댓글, 담당자, 세션 정보는 읽거나 복사하지 않는다.
- 읽은 값은 네트워크나 별도 저장소로 전송하지 않는다.
- 제목은 HTML에서 escape해 업무 제목이 임의 markup으로 실행되거나 깨지지 않게 한다.
- 기능은 사내 Jira origin으로만 URL을 구성한다.

## 결정 사항과 고민 내용

### Markdown 대신 HTML + plain text

초기부터 특정 Markdown 문자열을 만드는 방식은 선택하지 않았다. 메신저와 문서 편집기 등 rich text 대상에서는 실제 링크를 유지하고, 그 외 환경에서는 읽기 쉬운 plain text로 대체하는 편이 범용성이 높기 때문이다.

### 모든 보드 허용

초기 통합 버전은 이관 원본의 사용 범위를 그대로 따라 `NPT / 2146`으로 제한했다. 실제 사용 중 `NPT / 2147`에서도 같은 기능이 필요하다는 사실이 확인됐다. 업무 번호와 제목을 복사하는 행위는 특정 프로젝트·보드 정책에 의존하지 않으므로 프로젝트 키와 보드 ID 제한을 제거했다.

### 제목 포함을 별도 버튼으로 제공

하나의 버튼이 설정에 따라 형식을 바꾸거나 메뉴를 여는 방식보다 두 형식을 화면에서 바로 선택하는 방식을 택했다. 버튼 영역이 넓어지는 비용이 있지만 반복 작업의 클릭 수와 모호성을 줄인다.

### 제목은 클릭 시점 DOM에서 읽기

Jira REST API는 더 안정적인 데이터 계약을 제공할 수 있지만 추가 권한, 요청, 인증·오류 처리가 필요하다. 현재 dialog에 이미 제목이 존재하므로 DOM을 사용한다. 대신 Jira UI 변경과 제목 로딩 타이밍에 취약할 수 있음을 수용한다.

### 내부 기능 ID 유지

사용자 명칭은 `이슈 링크 복사`에서 `업무 링크 복사`로 변경했지만 내부 ID는 바꾸지 않았다. 저장된 설정과 migration 호환성을 지키기 위해 표시 이름과 식별자를 분리한다.

## 실패와 복구

- 지원 URL이 아니거나 선택 업무가 없으면 버튼을 표시하지 않는다.
- 현재 업무 번호 링크를 찾지 못하면 버튼을 표시하지 않는다.
- 제목 포함 복사 시 제목을 찾지 못하면 성공으로 처리하지 않는다.
- rich clipboard 실패 시 plain text로 대체한다.
- 모든 복사 방식이 실패하면 `복사 실패` 피드백을 표시하고 원본 Jira 화면은 그대로 유지한다.
- DOM 재렌더로 버튼이 제거되면 적용 조건이 유지되는 동안 다시 생성한다.

## 수용 기준

- 임의의 Jira 프로젝트와 보드 기본 화면에서 업무를 선택하면 두 버튼이 표시된다.
- `업무 링크 복사`는 선택 업무 번호를 정규 URL이 연결된 rich text와 동일한 plain text 번호로 복사한다.
- `업무 링크 복사(제목포함)`은 같은 링크 뒤에 현재 dialog 제목을 공백 하나로 구분해 추가한다.
- 제목의 HTML 특수문자가 클립보드 markup을 깨뜨리지 않는다.
- 버튼 클릭 시 처리 중, 성공 또는 실패 상태가 보이며 잠시 뒤 기본 문구로 복귀한다.
- 선택 업무가 바뀌면 새 업무 번호와 제목을 사용한다.
- Jira 서비스 또는 기능을 끄면 버튼이 제거되고, 다시 켜면 조건을 만족하는 화면에서 복구된다.
- Jira의 기본 링크 복사와 원본 업무 dialog는 확장 기능 실패 여부와 무관하게 계속 사용할 수 있다.

## 검증 기준

- URL parser가 `NPT / 2147`과 다른 프로젝트·보드도 허용하는지 단위 테스트한다.
- 제목 없는 payload와 제목 포함 payload의 plain/HTML 형식을 단위 테스트한다.
- 제목의 공백 정규화와 HTML escape를 단위 테스트한다.
- TypeScript typecheck, 전체 unit test, production build가 성공해야 한다.
- 실제 로그인된 Jira에서 업무 번호 링크, 제목 selector, 버튼 표시를 확인한다.
- rich editor와 plain text 입력란에 각각 붙여넣어 최종 형태를 확인하는 수동 E2E가 필요하다.

## 알려진 리스크와 열린 질문

- Jira의 dialog 구조나 `data-testid`가 바뀌면 버튼 또는 제목 추출이 중단될 수 있다.
- 제목이 아직 로딩 중인 순간 사용자가 제목 포함 버튼을 누르면 실패할 수 있다.
- 두 버튼이 Jira breadcrumb 영역의 가용 폭을 초과하는 화면 크기가 있는지 실제 사용 관찰이 필요하다.
- rich text 편집기마다 HTML clipboard 해석 방식이 달라 링크와 공백 표현이 다를 수 있다.
- backlog 등 보드 하위 view에서의 selectedIssue 지원을 향후 포함할지 결정이 필요하다.
- 현재 브라우저에 이전 content script가 남아 있으면 새 build와 다른 동작을 보일 수 있으므로 E2E 전에 확장 재로드와 페이지 새로고침이 필요하다.
