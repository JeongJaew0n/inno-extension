# Jira 업무 모달 전체 폭

- 상태: Active
- 최종 갱신일: 2026-09-15
- 내부 기능 ID: `issueModalWidth`
- 기본값: OFF

## 한 줄 요약

Jira 보드의 업무 상세 모달을 브라우저 화면 전체 크기로 넓히는 토글 버튼을 모달 헤더에 제공한다.

## 배경과 사용자 문제

보드에서 업무를 열면 상세가 모달로 뜬다. 이 모달은 **뷰포트와 무관하게 `1280 × 754`로 고정**돼 있다. 화면이 아무리 넓어도 좌우·상하에 여백이 남는다. 설명이 길거나 표·코드 블록이 많은 업무에서는 읽을 공간이 부족하다.

Jira에는 이를 넓히는 수단이 없다.

| 확인한 곳 | 결과 |
| --- | --- |
| 모달 우상단 버튼 | 관찰·공유·에이전트·`작업`·**사이드바로 전환**·닫기 |
| `작업(...)` 메뉴 17개 항목 | 전체 화면·확대·최대화 없음 |
| 전체 페이지 `/browse/` | 더 넓지만 **보드를 벗어나고** 뷰포트 전체도 아님 |

우상단 화살표는 전체 화면 토글이 아니라 `사이드바로 전환`이다. 오히려 **더 좁아진다.**

## 목표

- 보드 업무 모달을 뷰포트 전체 크기로 넓힌다.
- 토글 한 번으로 기본 크기와 전체 크기를 오간다.
- Jira 기본 UI와 데이터를 바꾸지 않는다.

## 비목표

- 백로그의 상세 패널은 대상이 아니다. 그쪽은 모달이 아니라 우측 도킹 `preview-panel`이고, 전체 폭으로 만들면 백로그 목록을 가린다.
- 우측 필드 컬럼 폭은 조정하지 않는다.
- 본문 가독성을 위한 별도 `max-width`는 두지 않는다.
- 전체 페이지 뷰로 대체하지 않는다. 보드를 벗어나기 때문이다.

## 적용 범위와 활성 조건

- Jira 서비스와 이 기능이 모두 ON일 때만 동작한다. **기본값은 OFF다.**
- 보드 업무 상세 모달(`role="dialog"`)이 열려 있을 때만 토글 버튼을 주입한다.
- 모달이 닫히면 버튼만 거둔다. 스타일 시트와 전체 폭 상태는 남겨 다음 모달에서 이어진다.

## 사용자 경험

- 토글 버튼은 `사이드바로 전환` 버튼 **왼쪽**에 놓는다. 사이트 기본 버튼의 순서를 바꾸지 않는다.
- 버튼은 현재 상태에 따라 `전체 폭으로 전환` / `기본 폭으로 전환`을 아이콘과 `aria-label`·`title`로 안내하고 `aria-pressed`로 상태를 노출한다.
- 주입한 버튼은 Shadow DOM으로 격리해 Jira 스타일과 섞이지 않는다.

## 동작 계약

전체 크기 상태는 `<html>`의 `data-inno-jira-wide` 속성으로 나타낸다. 스타일 시트는 한 번만 주입하고 토글은 속성만 바꾼다. 속성이 없으면 Jira 기본 크기 그대로다.

### 모달의 세 겹 구조

| 요소 | `data-testid` | 역할 |
| --- | --- | --- |
| 오버레이 | `…modal-dialog--blanket` | 이미 뷰포트 전체. 건드리지 않는다 |
| 위치 컨테이너 | `…modal-dialog--positioner` | `max-width`와 `top`·`bottom` 오프셋으로 제한 |
| 본체 | `…modal-dialog` | `width: 1280px` 고정 |

**폭과 높이를 막는 방식이 다르다.**

- 폭은 위치 컨테이너의 `max-width`와 본체의 `width`가 각각 막는다. 둘 다 풀어야 한다.
- 높이는 위치 컨테이너가 `position: absolute`에 `top: 60px; bottom: 59px; max-height`로 잡는다. **`height`만 늘리면 아래로 넘친다.** 오프셋을 0으로 만들어야 한다.

본체 높이는 `100vh`로 준다. `100%`로 주면 컨테이너 높이가 확정되기 전에 계산돼 본문 전체 높이까지 늘어난다.

### 선택자 규칙

`data-testid`만 사용한다. Jira의 원자 CSS 클래스는 빌드마다 해시가 바뀌므로 선택자로 쓰지 않는다. `!important`가 필요하다. 그 원자 클래스를 특이도로 이길 수 없기 때문이다.

## 설정과 기본값

| 항목 | 값 |
| --- | --- |
| 기능 기본값 | **OFF** |
| 설정 위치 | `chrome.storage.sync` |
| 상세 설정 | 없음 |

레이아웃을 크게 바꾸는 변경이라 기본값을 OFF로 둔다.

## 실패와 복구

- `data-testid`가 바뀌면 CSS가 아무 효과를 내지 못한다. **Jira 기본 동작이 그대로 남을 뿐 손상은 없다.**
- 기능을 끄거나 확장을 제거하면 스타일 시트와 속성을 함께 걷어낸다.
- 토글은 문서 구조를 바꾸지 않는다. 되돌리면 Jira가 계산한 원래 크기로 정확히 복귀한다.

## 수용 기준

- 기능이 OFF면 스타일 시트도 토글 버튼도 주입되지 않는다.
- 토글을 켜면 모달이 뷰포트 전체 크기가 되고, 끄면 원래 크기로 정확히 돌아온다.
- 모달을 닫았다 다시 열어도 상태가 유지된다.
- 사이트 기본 버튼의 순서와 동작이 변하지 않는다.
- 백로그 화면에서는 아무 영향이 없다.

## 검증 기준

실측으로 확인한다.

| 항목 | 기본 | 전체 크기 |
| --- | --- | --- |
| 모달 폭 (뷰포트 1920) | 1280 | 1920 |
| 모달 폭 (뷰포트 1512) | 1280 | 1512 |
| 모달 높이 (뷰포트 873) | 754 | 873 |
| 본문 컬럼 폭 (1920) | 928 | 1568 |
| 본문 레이아웃 높이 | 686 | 805 |

## 알려진 리스크와 열린 질문

- 본문 한 줄이 최대 1568px까지 넓어진다. 긴 문단은 읽기 불편할 수 있다. 사용자가 토글로 조절한다.
- 우측 필드 컬럼은 270px 그대로다. 남는 폭을 본문이 가져간다.
- 백로그 패널을 넓히는 별도 기능이 필요한지는 미정이다.
- Jira의 `data-testid`는 계약이 아니다. 바뀌면 조용히 동작하지 않는다.

## 변경 이력

- 2026-09-15: 기능을 추가했다. 보드 업무 모달의 폭·높이 제한을 풀어 뷰포트 전체 크기로 넓히는 토글을 모달 헤더에 제공한다. 기본값은 OFF다.
