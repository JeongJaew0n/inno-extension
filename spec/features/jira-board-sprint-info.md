# Jira 활성 스프린트 정보

- 상태: Active
- 최종 갱신일: 2026-11-03
- 내부 기능 ID: `boardSprintInfo`
- 기본값: ON

## 한 줄 요약

활성 스프린트 보드 상단 우리 줄에 스프린트 **기간·남은 일수·목표**를 보여준다. 페이지가 값을 들고
있지 않은 새 보드(2026-11)에서는 `스프린트 정보` 칩을 **누를 때** Jira API 로 읽는다.

## 배경과 사용자 문제

보드 화면 어디에도 스프린트 기간이나 목표가 표시되지 않는다. `스프린트 세부 정보` 아이콘을
눌러야 팝업으로 나온다. 스프린트가 언제 끝나는지 확인하려면 매번 눌러야 한다.

## 적용 범위와 활성 조건

- Jira 서비스와 이 기능이 모두 ON일 때 동작한다. **기본값은 ON이다.**
- **활성 스프린트 보드(`/boards/<id>`)에서만** 나타난다. 백로그는 대상이 아니다.
  주소는 `c/` 가 있는 것(예전)과 없는 것(새 보드, 2026-11) 둘 다 받는다.
- 스프린트를 쓰지 않는 보드(Kanban)에는 칩을 만들지 않는다.
- 활성 스프린트가 여럿이면 첫 번째 것만 보여준다.

## 사용자 경험

```
버전  Epic  유형  레이블  빠른 필터              스프린트 완료  그룹: 담당자
──────────────────────────────────────────────────────────────────────
[Jazz-v1.0-Sprint1 ▾]   📅 9/9 ~ 9/30 · 8일 남음 · <목표>     ← 우리 줄
```

**Jira 필터 줄에 끼우지 않는다.** 처음에는 `빠른 필터` 오른쪽에 붙였는데, 화면이 좁아지면
밀려서 **아예 안 보이는 수준까지** 줄었다. Jira 는 자기 필터를 `더 보기` 로 접어 버티지만 우리
것은 그럴 수 없다. 필터 아래에 우리 줄을 따로 둔다 — 예전 보드는 컨트롤 바 바로 뒤, 새 보드는
머리 영역 맨 끝에 한 줄을 통째로 쓴다.

### 칩 상태

| 상태 | 칩 | 언제 |
| --- | --- | --- |
| 처음 | `스프린트 정보` | 페이지가 날짜를 들고 있지 않다(새 보드) |
| 읽는 중 | `읽는 중…` | 누른 뒤 답을 기다린다. 누를 수 없다 |
| 표시 | `9/9 ~ 9/30 · 8일 남음 · 목표` | 페이지 상태에 날짜가 있거나(예전 보드, 새 보드에서 Jira 의 `스프린트 세부 정보` 를 연 뒤), 눌러서 읽었다 |
| 없음 | `활성 스프린트 없음` | 읽었더니 진행 중인 스프린트가 없다 |
| 실패 | `다시 시도` | 읽지 못했다. hover 에 이유가 나온다 |

어느 상태든 **누르면 Jira 에서 다시 읽는다.**

- 목표가 설정돼 있으면 기간 뒤에 붙는다. 없으면 기간만 나온다.
- **자리가 좁아지면 덜 중요한 것부터 뺀다.** 잘라내지 않는다.

| 자리 | 보이는 것 |
| --- | --- |
| 넉넉 | `9/9 ~ 9/30 · 8일 남음 · 목표` |
| 보통 | `9/9 ~ 9/30 · 8일 남음` |
| 좁음 | `8일 남음` |
| 아주 좁음 | 아이콘만 |

무엇을 먼저 버리는가 — 목표, 그다음 기간. **`남은 일수` 가 한눈에 가장 쓸모 있다.**
어느 단계든 전체 내용은 hover 에 그대로 남는다.

hover 문구는 세 줄이다.

```
Jazz-v1.0-Sprint1
2026-09-09 ~ 2026-09-30 (8일 남음)
목표: 설정되지 않음
```

> 목표가 없을 때 빈 줄로 두지 않고 **`설정되지 않음`** 이라고 적는다. 설정이 안 된 것인지 못 읽은
> 것인지 구분돼야 한다.

## 동작 계약

### 먼저 페이지가 들고 있는 것을 읽는다 — 요청 없음

| 보드 | 읽는 곳 | 날짜 |
| --- | --- | --- |
| 예전 보드 | `window.SPA_STATE.UIF_BOARD` | 있다. 처음부터 채운다 |
| 새 보드(2026-11) | Relay(GraphQL) 저장소. `page-layout.main` 의 React fiber 에서 올라가 찾는다 | 사용자가 Jira 의 `스프린트 세부 정보` 를 열기 전엔 없다 |

둘 다 페이지(MAIN world)의 것이라 content script 에서 보이지 않으므로 읽기 전용 브리지를 거친다.
브리지는 **읽기만** 하고 아무것도 바꾸지 않는다. 보드가 스프린트를 쓰는지(Kanban 인지)도 여기서 읽는다.

### 칩을 누를 때만 API 를 부른다

카탈로그 `usesNetwork: true`. `CLAUDE.md` 의 '네트워크는 예외다' 를 따른다. **화면을 연 것만으로는
요청하지 않는다**(2026-11-03 사용자 결정: 칩을 눌렀을 때만 읽기).

| 순서 | 요청 | 무엇을 |
| --- | --- | --- |
| 1 | `GET /rest/agile/1.0/board/{boardId}/sprint?state=active&maxResults=10` | 활성 스프린트의 이름 · 시작일 · 종료일 · 목표 |
| 2 | `GET /rest/greenhopper/1.0/gadgets/sprints/remainingdays?rapidViewId={boardId}&sprintId={id}` | Jira 가 센 남은 작업일(`{"days": N}`) |

- 둘 다 같은 오리진의 상대 경로, 세션 쿠키, `GET` 만이다. 토큰을 저장하지 않는다.
- 2번은 공개 문서에 없는 Jira Software API(대시보드 '스프린트 남은 일수' 가젯이 쓰는 것)다. Agile REST
  에는 남은 일수가 없고, 남은 일수는 보드의 근무일 설정을 따르므로 우리가 주말만 빼서 세면 휴일이
  어긋난다. 실측(2026-11-03): 진행 중 스프린트 `{"days":3}` = 화면 `3일 남음` = Relay
  `activeWorkingDaysRemaining` 3, 끝난 날이 지난 스프린트 `{"days":0}`.
- 2번이 실패하거나 모양이 다르면 **남은 일수만 빼고** 기간·목표는 보여준다.
- Kanban 보드는 1번에 400(`보드는 스프린트를 지원하지 않습니다.`)으로 답한다. 그래서 Kanban 이면 칩을
  만들지 않는다.

### 틀린 정보를 보여주느니 아무것도 보여주지 않는다

- 페이지 상태 경로가 사라지면 칩은 `스프린트 정보` 로 남고, 누를 때 API 로 읽는다. **보드를 망가뜨리지 않는다.**
- 날짜를 파싱하지 못하면 기간을 띄우지 않고 `다시 시도` 로 둔다.
- 브리지가 1초 안에 답하지 않으면 포기한다.

### 날짜 파싱

Jira가 주는 ISO 문자열의 오프셋에는 콜론이 없다(`+0900`). ES 명세의 `Date.parse`는 `+09:00`을
요구한다. V8이 관대할 뿐이므로 **콜론을 넣어 정규화한 뒤** 파싱한다. REST 와 Relay 는 `Z` 로 끝나는
UTC 문자열을 준다(실측 2026-11-03). 그대로 파싱된다.

## 수용 기준

- 활성 스프린트 보드에 기간과 남은 일수가 나타난다. 새 보드에서는 칩을 누르면 나타난다.
- 보드를 연 것만으로는 Jira API 요청이 나가지 않는다.
- 목표가 설정된 스프린트에서는 목표가 함께 나온다.
- Kanban 보드와 백로그 화면에는 나타나지 않는다.
- 상태를 읽지 못해도 보드가 정상 동작한다.
- 기능이 OFF면 아무것도 주입되지 않는다.

### 왜 잘렸었나

칩 호스트가 flex 항목인데 `min-width` 를 풀지 않아, 자리가 모자라도 **내용 폭 그대로 버티다가
바깥에서 잘렸다.** 우리 `text-overflow: ellipsis` 는 자기가 넉넉하다고 믿어 작동조차 하지 않았다
(실측: 호스트 80px, 안의 칩 142px, `scrollWidth === clientWidth`).

`min-width: 0` 을 풀어 줄어들 수 있게 하고, `ResizeObserver` 로 폭이 바뀔 때마다 들어가는 가장
자세한 문구를 다시 고른다.

## 알려진 리스크와 열린 질문

- **Jira 내부 상태 모양에 기댄다.** 빌드가 바뀌면 경로가 사라질 수 있고, 그때는 칩이 `스프린트 정보` 로 남는다.
- **남은 일수 API 는 공개 문서에 없다.** 사라지면 남은 일수만 빠진다.
- **SPA 이동 시 신선도를 확인하지 못했다.** 스프린트를 완료·시작한 직후 값이 옛것일 수 있다.
- 활성 스프린트가 여럿인 보드에서 확인하지 못했다.
