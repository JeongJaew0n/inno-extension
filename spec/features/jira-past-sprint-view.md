# Jira 지난 스프린트 보기

- 상태: Active
- 최종 갱신일: 2026-09-18
- 내부 기능 ID: `pastSprintView`
- 기본값: ON
- **이 확장에서 Jira API를 쓰는 유일한 기능이다**

## 한 줄 요약

활성 스프린트 보드에서 **종료된 스프린트**의 업무를 읽기 전용 패널로 본다.

## 배경과 사용자 문제

보드는 활성 스프린트만 보여준다. 지난 스프린트에 무엇이 있었는지 보려면 보고서나 검색으로
돌아가야 한다.

## API를 쓴다 — 특별 관리 대상

이 기능만 Jira API를 부른다. `CLAUDE.md`의 '특별 관리란'을 따른다.

| 규칙 | 이 기능에서 |
| --- | --- |
| 표시 | 카탈로그 `usesNetwork: true`. Popup에 `API` 배지 |
| 범위 | **`GET`만.** 클라이언트에 쓰기 메서드를 만들지 않았다 |
| 시점 | **스프린트 셀렉트를 열 때 목록을, 고를 때 업무를 부른다.** 보드를 여는 것만으로는 요청이 나가지 않는다 |
| 오리진 | `/rest/`로 시작하는 **상대 경로만** 받는다. 절대 URL은 거부한다 |
| 인증 | 브라우저 세션 쿠키. **토큰을 저장하지 않는다** |

### 부르는 요청

| 언제 | 요청 |
| --- | --- |
| 셀렉트를 처음 열 때 (1회) | `GET /rest/agile/1.0/board/{boardId}/sprint?state=active,closed` |
| 종료 스프린트를 고를 때 | `GET /rest/agile/1.0/sprint/{sprintId}/issue?fields=summary,status,issuetype,assignee,parent` |

업무 조회는 100건씩 나눠 온다. 응답의 `fields`가 134개라 **필요한 다섯 개만 달라고 한다.**

## 보드 카드를 바꾸지 않는다

**보드 위에 패널을 덮는다.** 이게 이 기능에서 가장 중요한 설계 결정이다.

카드를 지워도 React가 되살리지 않는 것을 실측으로 확인했다. 하지만 그건 React가 **자기 가상 DOM이
맞다고 믿는 것만 고치기 때문**이고, 그때부터 가상 DOM과 실제 화면이 어긋난 채 남는다.

| 사용자 행동 | 어긋난 DOM에서 |
| --- | --- |
| 카드 드래그 | 엉뚱한 업무의 상태가 바뀔 수 있다 |
| 필터 변경 | 지난 스프린트 카드에 현재 필터가 먹는다 |
| **`스프린트 완료`** | **보이는 것과 실제 대상이 다르다** |

가장 나쁜 것은 **되돌릴 수 없는 동작이 사용자가 모르는 대상에 걸리는 것**이다. 패널은 밑의 보드를
건드리지 않으므로 이 위험이 구조적으로 없다.

## 사용자 경험

```
버전 Epic 유형 레이블 빠른필터  [스프린트 ▾]   📅 9/9 ~ 9/30 · 8일 남음

┌─ Sprint0   2026-08-12 ~ 2026-08-26   [읽기 전용]        [닫기] ─┐
│  해야 할 일 3     IN-PROGRESS 5     완료 12                    │
│  ...카드...       ...카드...        ...카드...                  │
└──────────────────────────────────────────────────────────────┘
```

- 셀렉트에서 `활성 스프린트`를 다시 고르거나 `닫기`를 누르면 패널이 사라진다. **새로고침이 필요 없다**
- 컬럼은 업무 **상태 이름**으로 묶고, 상태 분류(`new` → `indeterminate` → `done`) 순서로 놓는다
- 카드를 누르면 업무가 **새 탭**에서 열린다. 보드를 떠나지 않는다
- 드래그·편집은 없다. 끝난 스프린트다

## 실패와 복구

| 상황 | 보여주는 것 |
| --- | --- |
| 401·403 | `이 보드를 볼 권한이 없습니다.` |
| 429 | `Jira 요청이 너무 잦습니다. 잠시 뒤 다시 시도하세요.` |
| 연결 실패 | `Jira에 연결하지 못했습니다.` |
| 업무 0건 | `이 스프린트에는 업무가 없습니다.` |

**조용히 실패하지 않는다.** 어느 경우든 패널 안에 이유가 남고 보드는 그대로다.

## 수용 기준

- 보드를 여는 것만으로는 **요청이 나가지 않는다**
- 종료 스프린트를 고르면 그 업무가 상태별로 보인다
- 닫으면 원래 보드가 그대로 남는다. 새로고침이 필요 없다
- 보드 카드가 하나도 사라지거나 바뀌지 않는다
- 권한이 없으면 이유가 보인다
- 기능이 OFF면 셀렉트가 나타나지 않고 요청도 없다

## 알려진 리스크와 열린 질문

- 보드의 **실제 컬럼 설정**을 따라가지 않는다. 상태 이름으로 묶는다. 컬럼 설정 연동은 다음 단계
- 스윔레인·그룹 기준을 반영하지 않는다
- 업무가 아주 많은 스프린트는 요청이 여러 번 나간다(100건씩)
- Atlassian이 Agile API를 바꾸면 깨진다. 공개 API라 사내 비공식 엔드포인트보다는 안정적이다

## 변경 이력

- 2026-09-18: 기능을 추가했다. 이 확장에서 API를 쓰는 첫 기능이다.
