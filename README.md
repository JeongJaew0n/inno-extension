  # Inno Extension

  사내 업무 사이트 다섯 곳의 잔손질을 줄이는 Chrome 확장

  [최신 릴리즈](https://github.com/JeongJaew0n/inno-extension/releases/latest) · [제품 Spec](./spec/README.md) · [변경 이력](./spec/product-overview.md#변경-이력)

## 무엇을 하나

아마란스, Jira, Confluence, GitHub Enterprise, GitLab 화면에 작은 버튼과 스위치를 붙입니다.
링크를 원하는 형식으로 복사하고, 문서를 Markdown 으로 옮기고, 매번 같은 값을 넣던 입력을 한 번에 채웁니다.

- **누르기 전에는 아무것도 하지 않습니다.** 복사·변환·입력은 사용자가 버튼을 눌렀을 때만 일어납니다.
- **저장·제출은 사용자 몫입니다.** 확장은 편집 중인 초안만 바꾸고, 저장·생성·발행 버튼은 누르지 않습니다.
- **데이터를 밖으로 보내지 않습니다.** 모든 처리는 브라우저 안에서 끝납니다. 사이트 API 를 부르는 기능은 하나뿐이고, 읽기만 합니다([아래](#네트워크를-쓰는-기능)).
- **고장 나도 원래 사이트는 그대로 씁니다.** 사이트 화면이 바뀌어 기능이 못 붙으면 그 버튼만 안 보입니다.

| 사이트 | 주소 |
| --- | --- |
| 아마란스 | `gw.innogrid.com` |
| Jira | `pms-innogrid.atlassian.net` (`/jira` · `/browse` · `/issues`) |
| Confluence | `pms-innogrid.atlassian.net/wiki` |
| GitHub Enterprise | `github.nhnent.com` |
| GitLab | `rnd-app.innogrid.com` |

## 설치

Chrome 웹 스토어에는 없습니다. 릴리즈 ZIP 을 받아 **압축해제된 확장**으로 올립니다.

1. [최신 릴리즈](https://github.com/JeongJaew0n/inno-extension/releases/latest)에서 `inno-extension-<version>.zip` 을 받습니다.
2. 압축을 풉니다. **이 폴더 위치는 앞으로 바꾸지 마세요** — 이유는 [업데이트](#업데이트)에 있습니다.
3. `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기 → **압축해제된 확장 프로그램을 로드합니다** → 방금 푼 폴더 선택.
4. 이미 열려 있던 사내 사이트 탭은 새로고침합니다.

현재 버전: [v0.14.0](https://github.com/JeongJaew0n/inno-extension/releases/tag/v0.14.0)

### 업데이트

자동으로 갱신되지 않습니다. 새 ZIP 을 **같은 폴더에 덮어쓰고**, 두 번 새로고침합니다.

1. `chrome://extensions` 에서 Inno Extension 카드의 ↻
2. 열려 있던 사내 사이트 탭

1 을 빼면 옛 코드가 계속 돌고, 2 를 빼면 기존 탭의 버튼이 사라집니다.

> **폴더를 옮기면 설정이 날아갑니다.** `manifest.json` 에 `key` 가 없어서 확장 ID 가 폴더 경로로 정해집니다. 경로가 바뀌면 ID 가 바뀌고, `chrome.storage.sync` 에 있던 ON/OFF 와 저장 문구가 새 ID 에서는 보이지 않습니다.

이 과정은 [프로젝트 스킬 `update-release`](./.codex/skills/update-release/SKILL.md)가 대신할 수 있습니다. 설치 폴더를 찾고, 버전을 비교하고, 백업한 뒤 덮어씁니다.

## 기능

Popup 에서 사이트 단위로, 그 안에서 기능 단위로 켜고 끕니다. 표에 `OFF` 로 적힌 것만 기본으로 꺼져 있습니다.

### 아마란스

| 기능 | 하는 일 |
| --- | --- |
| 헤더 출퇴근 버튼 | 원본 출근·퇴근 버튼을 헤더에서도 누를 수 있게 합니다. 활성 상태는 원본을 따라갑니다. **인사말 복사**는 오늘 출근 시각으로 `n시 n분 출근입니다.` 를 복사합니다 |
| 신청서 제목 자동채움 | 근태신청서 상신 단계의 `제목` 옆 **자동채움**이 저장한 문구를 넣습니다. 문구는 **양식별로** 둘 수 있고(연차휴가신청서, 외근신청서 …), 없으면 기본 문구를 씁니다. 왼쪽 **⚙** 로 그 자리에서 모달을 열어 고칩니다. Popup 에서도 같은 값을 고칠 수 있습니다 |
| 통합알림 새로고침·인증번호 복사 | `전체` 탭에서 탭을 오가지 않고 목록을 갱신합니다. `[메일]` 알림에 인증 문맥과 함께 나온 4~6자리 번호에 **복사** 버튼을 붙입니다. 날짜·업무번호처럼 인증 문맥이 없는 숫자는 건드리지 않습니다 |

### Jira

**업무 링크 복사** — 보드에서 고른 업무와 `/browse/NPT-38` 같은 상세 화면에서 씁니다.

| 버튼 | 결과 |
| --- | --- |
| 업무 링크 복사 | `NPT-38` |
| 업무 링크 복사(제목포함) | `NPT-38 업무 제목` |

HTML 붙여넣기를 받는 곳에서는 번호가 해당 업무 링크로 붙습니다.

**업무 생성 모달**

| 기능 | 하는 일 |
| --- | --- |
| 업무 생성 날짜 단축 | 모달 위쪽 **오늘부터 시작**이 시작 날짜를 오늘, 기한을 오늘+3일로 넣습니다 |
| 업무 생성 템플릿 삽입 | 설명이 비어 있을 때 첫 글자로 `$` 를 치면 템플릿 목록이 뜹니다. 고르면 Markdown 원문이 아니라 **제목·목록 서식으로** 들어가고, `$` 는 남지 않습니다. `$버그` 처럼 이어 치면 제목으로 거릅니다. 지금은 내장 템플릿 다섯 개(작업·버그·에픽·하위 작업·문서)만 있습니다. 사용자 템플릿 관리 화면은 아직 없습니다 |

**업무 설명**

| 기능 | 하는 일 |
| --- | --- |
| 클릭 편집 방지 | `설명` 라벨 줄에 스위치를 붙입니다. 켜면 본문을 클릭해도 편집이 열리지 않고 **편집** 버튼으로만 들어갑니다. 링크·펼치기·체크박스는 그대로 눌립니다. 스위치는 전역 설정이라 Jira 화면, Popup, 다른 탭이 같은 값을 씁니다. 처음엔 꺼져 있습니다 |
| 설명 Markdown 복사 | 설명 본문을 Markdown 으로 복사합니다. 댓글은 빠집니다. 편집 중에도 편집기 문서를 직접 읽어 긴 코드 블록이 잘리지 않습니다 |
| 설명 편집 버튼 | 편집 중일 때 `설명` 제목 옆에 **취소**·**저장**을 붙입니다. 아래쪽 버튼을 대신 누르므로 동작이 같습니다 |
| 설명 Markdown 변환 | 편집기 툴바의 **Markdown 변환**이 두 단계를 차례로 돕니다. ① 본문 코드 블록이 전부 Markdown 문서로 보이면 코드 블록을 벗기고, ② 문단으로 남은 Markdown 을 제목·표·목록으로 바꿉니다. Jira 에는 Mermaid 앱이 없어 다이어그램은 만들지 않습니다. 저장은 사용자가 합니다 |

**보드·백로그**

| 기능 | 하는 일 |
| --- | --- |
| 활성 스프린트 정보 | 컨트롤 바 아래에 **기간 · 남은 일수 · 목표**를 한 줄로 보여 줍니다. 좁아지면 목표 → 기간 순으로 빼고 `남은 일수`를 끝까지 남깁니다. 값은 페이지가 이미 가진 것을 읽습니다 |
| 지난 스프린트 보기 | 셀렉트에서 종료된 스프린트를 고르면 그 업무를 읽기 전용 패널로 띄웁니다. 보드 카드는 건드리지 않고, 닫으면 원래 보드로 돌아옵니다. **API 를 쓰는 유일한 기능입니다** |
| 백로그 prefix 태그 | 업무 추가 입력칸 맨 앞에서 `/` 를 치면 `[INFRA]`, `[CI/CD]` 같은 태그 목록이 뜹니다. `↑↓` 로 고르고 `Enter`/`Tab` 으로 넣습니다. 문장 중간의 `/` 는 무시합니다. 내장 태그 아홉 개는 숨길 수만 있고, 사용자 태그는 Popup 에서 추가·수정·삭제합니다 |
| 업무 모달 전체 폭 `OFF` | 보드 업무 모달(`1280 × 754` 고정)을 브라우저 전체 크기로 넓히는 토글을 헤더에 붙입니다 |

## 설정

도구 모음의 아이콘을 누르면 Popup 이 열립니다.

- 사이트 카드의 스위치로 그 사이트 기능을 통째로 켜고 끕니다. 다시 켜면 기능별 선택이 그대로 돌아옵니다.
- 카드를 열면 기능별 스위치, 적용 화면, 세부 설정이 있습니다.
- 실제로 도는지는 `사이트 ON && 기능 ON` 으로 정해집니다.
- 일부 기능(prefix 태그 관리 등)은 사이트 화면의 링크로 설정 창을 바로 엽니다.

설정은 `chrome.storage.sync` 에 버전 붙은 형식으로 저장됩니다.

## 권한과 데이터

| 항목 | 내용 |
| --- | --- |
| 권한 | `storage` 하나. `host_permissions`, `scripting`, `downloads` 는 없습니다 |
| 실행 위치 | 위 다섯 사이트 주소에서만 content script 가 돕니다. Jira·Confluence 편집기를 다루려고 페이지 쪽(MAIN world) 스크립트를 함께 씁니다 |
| service worker | 사이트 화면에서 **설정 창을 여는 일** 하나만 합니다 |
| 인증 정보 | 쿠키·토큰·비밀번호를 읽거나 저장하지 않습니다 |
| 클립보드 | 사용자가 복사 버튼을 누를 때만 씁니다 |

### 네트워크를 쓰는 기능

화면에 이미 있는 것만 읽고 쓰는 것이 원칙입니다. 이 원칙을 벗어나는 기능은 Popup 에 배지로 표시하고 다음 규칙을 지킵니다.

| 규칙 | 내용 |
| --- | --- |
| 무엇을 | 읽기(GET)만 |
| 언제 | 사용자가 그 기능을 실제로 쓸 때만. 화면을 여는 것만으로는 요청하지 않습니다 |
| 어디로 | 그 사이트 자신의 주소로만. 로그인 세션을 그대로 쓰고 토큰을 저장하지 않습니다 |

지금 해당하는 기능은 **지난 스프린트 보기** 하나입니다. 스프린트 셀렉트를 열 때 목록을, 고를 때 업무를 한 번씩 요청합니다. 자세한 요청 목록은 [spec](./spec/features/jira-past-sprint-view.md)에 있습니다.

## 안 될 때

| 증상 | 확인할 것 |
| --- | --- |
| 버튼이 안 보인다 | ① Popup 에서 사이트·기능이 모두 ON 인지 ② 지금 화면이 기능의 적용 화면인지 ③ `chrome://extensions` 에서 ↻ ④ 사이트 탭 새로고침 |
| 새로 빌드했는데 그대로다 | 빌드만으로는 열린 탭에 반영되지 않습니다. 확장 ↻ → 사이트 탭 새로고침 |
| 변환 결과가 이상하다 | 저장하기 전에 실행 취소로 되돌리고, 콘솔의 `[Inno Extension]` 로그와 화면을 함께 남겨 주세요 |

## 개발

```bash
npm install
npm run build        # typecheck + 테스트 + dist/ 빌드
```

`chrome://extensions` 에서 `dist/` 를 로드합니다. 고친 뒤에는 다시 빌드하고 확장 ↻ → 사이트 탭 새로고침.

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | Vite 개발 서버 |
| `npm run typecheck` | TypeScript 검사 |
| `npm test` | 단위 테스트 (`node --test`) |
| `npm run check` | typecheck + test |
| `npm run build` | check 후 `dist/` 빌드 |
| `npm run test:e2e` | 빌드한 확장을 헤드리스 Chrome 에 올려 가짜 사이트 화면에서 전 기능을 눌러 봅니다 |
| `npm run package` | build 후 `release/inno-extension-<version>.zip` 생성과 무결성 검사 |
| `npm run design:sync` | `design/` 정본에서 토큰·컴포넌트 CSS 를 다시 뽑습니다 |

### 구조

```text
src/
├── catalog/      사이트·기능 목록의 정본. Popup 과 설정 기본값이 여기서 나온다
├── platform/     사이트와 무관한 공용 부품
│   ├── runtime/    MutationObserver 하나로 기능들의 reconcile() 을 돌린다
│   ├── settings/   버전 붙은 설정 형식과 저장소
│   ├── design/     주입 UI 공용 토큰·컴포넌트 CSS (생성물)
│   ├── editor/     Atlassian 편집기 공용 — MAIN world 브리지, Markdown 변환 단계
│   ├── adf/        Markdown ↔ ADF 변환기
│   ├── markdown/   화면 → Markdown 변환
│   ├── clipboard/  평문·HTML 클립보드 출력
│   └── messaging/  content script ↔ service worker 메시지
├── sites/<siteId>/features/<featureId>/   사이트별 기능
├── popup/        설정 화면
└── background/   설정 창을 여는 service worker
design/           디자인 시스템 정본. 빌드와 분리돼 있다
spec/             제품·기능 명세 (행동 계약의 정본)
docs/             계획, 조사, 오류 기록, 용어
tests/            단위 테스트와 e2e 하네스
```

기능은 "지금 화면에 무엇이 있어야 하나"만 판단하고, 있으면 두고 없으면 만듭니다. 여러 번 불려도 결과가 같아야 합니다. 꺼지면 `dispose()` 가 자기가 만든 DOM·스타일·타이머·리스너를 치웁니다. 주입 UI 는 Shadow DOM 안에 둬서 사이트 스타일과 섞이지 않습니다.

### 기능을 추가하려면

`카탈로그 → 설정 기본값 → 사이트 런타임 → spec → README` 순서입니다. 카탈로그(`src/catalog/sites.ts`)에 없는 기능은 Popup 에 나오지 않습니다. 네트워크가 필요하면 카탈로그에 `usesNetwork: true` 를 달아야 테스트가 통과합니다. 표시 없이 요청 코드를 넣으면 테스트가 깨집니다.
